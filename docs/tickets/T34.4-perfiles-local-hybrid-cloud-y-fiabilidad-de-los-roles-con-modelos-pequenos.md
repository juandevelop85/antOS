# T34.4 · Perfiles `local` / `hybrid` / `cloud` y Fiabilidad de los Roles con Modelos Pequeños

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 34 (Modelos locales de serie)
> **Prioridad:** 🟡 Media
> **Fecha:** September 2026
> **Dependencias:** T34.2 (contexto, `doctor`, `auto` local), T19.4 (modelos
> por rol), T33.3 (roles sobre el runtime), T33.5 (evaluación y `eval diff`).
> **Origen:** Los valores por defecto de `LlmConfig::get_role_model`
> contradicen el objetivo de «todo con modelos gratuitos»: Arquitecto →
> `openrouter:deepseek/deepseek-r1:free`, QA y Auditor →
> `groq:llama-3.3-70b-versatile`; solo el Coder es local. Una instalación
> sin claves no puede correr el pipeline de roles aunque tenga Ollama sano.
> Y la primera sesión con el 7B (T33.5 §3) dejó la fiabilidad del escenario
> Rust en 2/5 con n=1 por caso: los prompts y toolsets de los roles se
> escribieron pensando en modelos grandes, y no hay una medida repetida
> que diga si un cambio los mejora.

## Descripción

Dos mitades que se apoyan mutuamente: **perfiles** que fijan de un golpe
qué modelo usa cada rol según lo que la máquina tiene, y **medida
repetida** que convierte «funciona a veces» en un número que se puede
subir cambiando prompts, `format` y toolsets.

### 1. Perfiles

`antos llm profile <local|hybrid|cloud>` escribe `role_models` y
`role_steps` en `LlmConfig`:

| Perfil | Arquitecto | Coder | QA | Auditor | Requiere |
|---|---|---|---|---|---|
| `local` | Ollama, modelo «grande» de la tabla de RAM | Ollama, modelo «código» | Ollama, modelo «rápido» | Ollama, modelo «grande» | solo Ollama sano |
| `hybrid` | nube gratuita con clave presente (OpenRouter / Groq / Gemini) | Ollama | Ollama | nube gratuita | Ollama + ≥ 1 clave |
| `cloud` | como hoy (`get_role_model` actual) | como hoy | como hoy | como hoy | claves |

Los nombres «grande / código / rápido» se resuelven contra la tabla de RAM
de T34.2 (p. ej. 18 GB → `qwen2.5-coder:14b` no cabe con 16k de contexto;
el perfil elige `7b` para los tres y lo dice). `antos llm profile` sin
argumento muestra el activo y qué modelo tocó cada rol.

**El perfil por defecto de una instalación limpia es `local`**: si
`role_models` está vacío y `active_provider` es `auto`, `get_role_model`
devuelve el modelo local de `doctor`, no una URL de OpenRouter. El
comportamiento actual queda íntegro bajo `cloud`. `hybrid` se aplica solo
si hay clave; si no, avisa y aplica `local`.

### 2. Fiabilidad con modelos pequeños

Cambios en el runtime y los roles, cada uno medido antes y después:

- **Salida estructurada forzada.** El plan del Arquitecto y el veredicto
  del Auditor son JSON tipado; con Ollama se pide con `format: <JSON
  Schema>` (Ollama ≥ 0.5) en vez de confiar en que el modelo lo escriba
  bien. Igual en OpenAI-compat donde haya `response_format`. Claude sigue
  con `tool_use`, que ya lo garantiza.
- **Toolsets por tamaño.** Un 7B con doce herramientas confunde `fs.write`
  con `fs.patch`; `Role.toolset` gana una variante reducida (`compact`)
  que se activa cuando el modelo del rol es local y pequeño (umbral en la
  tabla de modelos): Coder = `fs.read`, `fs.patch`, `test.run`,
  `finalizar`; QA = `test.run`, `finalizar`.
- **Argumentos malformados → un reintento dirigido.** Cuando
  `Catalog::validate` rechaza una llamada por tipo/campo (no por política),
  el runtime devuelve el error **junto al esquema del parámetro** y
  permite un reintento sin consumir paso de presupuesto (una vez por
  llamada). Los rechazos por política siguen contando.
- **Prompts por rol en `agent/prompts/*.txt`** revisados con un modelo de
  7B: frases cortas, un ejemplo de llamada, «llama a `finalizar` en cuanto
  `test.run` esté en verde» al principio y al final. Cada cambio de prompt
  va con su medida en el ticket.

### 3. Medida

- `antos eval agent --live --provider ollama --repeat N` ejecuta cada caso
  N veces y guarda **tasa de éxito, mediana de pasos y de segundos**, no
  un único run. `eval diff` compara tasas y solo señala regresión si la
  caída supera un margen configurable (5 repeticiones tienen ruido).
- Job **nocturno** en GitHub Actions (`schedule:`), separado de `ci.yml`,
  que arranca Ollama por `nix run`, descarga `qwen2.5-coder:7b` (caché de
  Actions para `OLLAMA_MODELS`), ejecuta `--live --repeat 5` sobre los
  casos `live = true` y sube el JSON como artefacto. No bloquea PRs: es
  la serie histórica contra la que se mira antes de tocar un prompt.
- Los resultados con n=5 de este ticket se anotan en el propio ticket
  (antes / después de cada cambio), como hizo T33.5 §3.

## Alcance Técnico

- **`llm/config.rs`:** `Profile { Local, Hybrid, Cloud }`, `apply_profile`,
  `get_role_model` con el nuevo valor por defecto y la resolución por
  tabla; tests de los tres perfiles con y sin claves.
- **`agent/providers.rs`:** `format` en Ollama y `response_format` en
  OpenAI-compat cuando el `ToolSpec` terminal del rol declara esquema de
  salida; el reintento por validación en `agent/mod.rs`.
- **`agent/roles.rs`:** `toolset_compact`, criterio de activación por
  modelo; `agent/prompts/*.txt` revisados.
- **`agent/eval.rs`:** `--repeat`, agregados por caso, `diff` sobre tasas.
- **`.github/workflows/agents-nightly.yml`** (nuevo).
- **Manual §4.2:** perfiles, qué esperar de cada tamaño de modelo, y el
  ritual «evaluar → cambiar → evaluar → diff» con `--repeat`.

## Criterios de Aceptación

- `antos llm profile local` en una máquina con solo Ollama deja los
  cuatro roles en modelos locales que caben en RAM con 16k de contexto;
  `antos agent run <ticket> --auto` llega a `ReadyForApproval` sin clave.
- Test: `LlmConfig` limpia + `auto` → `get_role_model("architect")` es
  local; bajo `cloud` devuelve el valor de hoy.
- Test: un plan del Arquitecto devuelto como texto libre por un Ollama
  simulado **con** `format` no ocurre (el cuerpo enviado lleva el esquema);
  el runtime rechaza y reintenta una llamada con argumento malformado sin
  consumir paso, y no reintenta un rechazo por política.
- Test: el Coder con modelo pequeño recibe `toolset_compact`; con Claude,
  el completo.
- `antos eval agent --live --provider ollama --repeat 5` produce tasas por
  caso; `eval diff` con dos JSON de ejemplo (tasa 5/5 → 2/5) señala
  regresión y (5/5 → 4/5) no.
- Fiabilidad del escenario Rust con `qwen2.5-coder:7b`, n=5, anotada en el
  ticket antes y después; objetivo ≥ 4/5 en el Mac de 18 GB. Si no se
  alcanza, el ticket documenta qué cambio aportó qué y qué queda.
- Job nocturno en verde al menos una vez con el artefacto subido.
- `cargo test --workspace`, clippy `-D warnings`, `fmt`; CI verde.
