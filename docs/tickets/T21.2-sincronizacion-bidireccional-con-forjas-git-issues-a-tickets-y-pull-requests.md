# T21.2 · Sincronización Bidireccional con Forjas Git: Issues a Tickets y Pull Requests

> **Estado:** ⏳ Pendiente  
> **Fase:** Fase 21  
> **Fecha:** September 2026

## Descripción
Integrar antOS bidireccionalmente con las forjas de código colaborativas más extendidas (GitHub y GitLab) a través de `antos issue` y `antos pr`. Permite importar *Issues* remotos convirtiéndolos automáticamente en tickets técnicos estructurados en `docs/tickets/`, despacharlos al equipo de agentes `antFlow` en *worktrees* efímeros y, tras la certificación del Auditor, publicar el *Pull Request / Merge Request* correspondiente con descripción arquitectónica, diagrama de impacto, resumen de pruebas y enlaces cruzados.

## Alcance Técnico
1. **Cliente de Forjas Git y Autenticación Segura (`system/antosd/src/forge/`):**
   - Conectores HTTP para API REST de GitHub (`api.github.com`) y GitLab (`gitlab.com/api/v4`).
   - Gestión de tokens de acceso (`GITHUB_TOKEN`, `GITLAB_TOKEN`) almacenados de forma segura en la bóveda de secretos (`system/antosd/src/vault.rs`).
   - Detección automática del repositorio remoto a partir del `origin` configurado en Git.
2. **Importación y Traducción de Issues a Tickets Técnicos (`antos issue sync / import`):**
   - Descarga del título, cuerpo, etiquetas y comentarios del issue.
   - El rol *Arquitecto* estructura la especificación convirtiéndola al formato maestro de antOS: `docs/tickets/T-GH-<numero>-<slug>.md`, extrayendo criterios de aceptación tangibles.
3. **Generación y Publicación Automatizada de Pull Requests (`antos pr create`):**
   - Una vez que el ticket es completado en el worktree y certificado por el Auditor:
     - Push de la rama aislada al repositorio remoto.
     - Generación del cuerpo del PR: resumen del problema, cambios implementados por componente, reporte de tests de QA y firma criptográfica de auditoría.
     - Creación del PR asociando el issue original (`Fixes #<numero>`).
4. **Comandos CLI:**
   - `antos issue list`: Lista los issues abiertos del repositorio remoto.
   - `antos issue import <id_o_url>`: Importa un issue remoto y genera el ticket local.
   - `antos pr create [--draft]`: Publica el Pull Request del ticket actual en la forja.
   - `antos pr status`: Consulta el estado de revisión e integración continua del PR remoto.
5. **Pruebas y Verificación:**
   - Pruebas unitarias de parsing de respuestas JSON de GitHub/GitLab.
   - Generación estructurada de plantillas markdown para Pull Requests.

## Criterios de Aceptación
* Es posible importar un issue remoto generando un ticket markdown conforme a las convenciones de antOS.
* `antos pr create` formula un PR con descripción técnica, desglose de archivos y reporte de pruebas.
* Las credenciales de API se obtienen de la bóveda de secretos sin exponerse en logs.
* `cargo test --workspace` pasa al 100% sin advertencias ni regresiones.
