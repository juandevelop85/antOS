# T21.2 · Sincronización Bidireccional con Forjas Git: Issues a Tickets y Pull Requests

> **Estado:** ✅ Completado  
> **Fase:** Fase 21  
> **Fecha:** September 2026

## Descripción
Integrar antOS bidireccionalmente con las forjas de código colaborativas más extendidas (GitHub y GitLab) a través de `antos issue` y `antos pr`. Permite importar *Issues* remotos convirtiéndolos automáticamente en tickets técnicos estructurados en `docs/tickets/`, despacharlos al equipo de agentes `antFlow` en *worktrees* efímeros y, tras la certificación del Auditor, publicar el *Pull Request / Merge Request* correspondiente con descripción arquitectónica, diagrama de impacto, resumen de pruebas y enlaces cruzados.

## Alcance Técnico
1. **Cliente de Forjas Git y Autenticación Segura (`system/antosd/src/forge.rs`):**
   - Conectores HTTP para API REST de GitHub (`api.github.com`) y GitLab (`gitlab.com/api/v4`).
   - Gestión segura de tokens de acceso (`GITHUB_TOKEN`, `GITLAB_TOKEN`) consultando la bóveda de secretos (`system/antosd/src/vault.rs`) o variables de entorno sin exponer credenciales en bitácoras.
   - Detección automática del repositorio remoto a partir del `origin` configurado en Git (formatos SSH y HTTPS).
2. **Importación y Traducción de Issues a Tickets Técnicos (`antos issue sync / import`):**
   - Descarga de título, descripción, etiquetas y metadatos del issue remoto.
   - El rol *Arquitecto* estructura la especificación convirtiéndola al formato maestro de antOS: `docs/tickets/T-GH-<numero>-<slug>.md` (o `T-GL-...`), extrayendo criterios de aceptación tangibles.
3. **Generación y Publicación Automatizada de Pull Requests (`antos pr create` / `pr status`):**
   - Detección de la rama de trabajo (`ticket/T-GH-<num>`) y rama base (`master`/`main`).
   - Generación del cuerpo del PR: resumen del problema (`Fixes #<numero>`), cambios implementados por componente, reporte de tests de QA y certificación criptográfica de auditoría.
   - Consulta de estado e inspección de CI checks vía `antos pr status`.
4. **Comandos CLI y Capacidades:**
   - `antos issue list`: Lista los issues abiertos del repositorio remoto.
   - `antos issue import <id_o_url>`: Importa un issue remoto y genera el ticket local.
   - `antos pr create [--draft] [--title <t>] [--base <b>]`: Publica el Pull Request en la forja.
   - `antos pr status [numero]`: Consulta el estado de revisión e integración continua del PR remoto.
   - Capacidades declarativas: `issue.list.toml`, `issue.import.toml`, `pr.create.toml`, `pr.status.toml`.
   - Protocolo IPC: `Request::{ListRemoteIssues, ImportRemoteIssue, CreatePullRequest, GetPullRequestStatus}` y eventos correspondientes.
5. **Pruebas y Verificación:**
   - Pruebas unitarias de parsing de URLs remotas (HTTPS y SSH para GitHub y GitLab).
   - Generación estructurada de plantillas markdown de tickets técnicos y Pull Requests.
   - Validación del ciclo completo en tests de protocolo, IPC y planificador.

## Criterios de Aceptación
* [x] Es posible importar un issue remoto generando un ticket markdown conforme a las convenciones de antOS.
* [x] `antos pr create` formula un PR con descripción técnica, desglose de archivos y reporte de pruebas.
* [x] Las credenciales de API se obtienen de la bóveda de secretos sin exponerse en logs.
* [x] `cargo test --workspace` pasa al 100% sin advertencias ni regresiones (194 tests en antosd + 31 en protocolo + 3 en builder).
