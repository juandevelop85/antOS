# T22.4 · Capa de Abstracción de Runtime de Plataforma (`PlatformRuntime`)

> **Estado:** ✅ Completado  
> **Fase:** Fase 22  
> **Fecha:** September 2026

## Descripción
Diseñar e implementar una capa de abstracción de plataforma (`PlatformRuntime`) para unificar la gestión de recintos de seguridad (*sandboxes*), control de cuotas de recursos y telemetría de bajo nivel entre Linux, macOS y el kernel propio de antOS. En el estado actual, subsistemas como eBPF LSM, Cgroups v2, KVM / Cloud-Hypervisor y Wayland Layer Shell conviven con stubs o simulaciones parciales en plataformas que no son Linux. Este ticket formaliza un trait `PlatformRuntime` que permite saber explícitamente el nivel de fidelidad de cada subsistema en el host actual, evitando comportamientos ambiguos y proporcionando herramientas de diagnóstico claras (`antos doctor`).

## Alcance Técnico
1. **Definición del Trait de Plataforma (`system/antosd/src/runtime/`):**
   - Diseñar `PlatformRuntime` con los métodos fundamentales del sistema operativo:
     ```rust
     pub trait PlatformRuntime: Send + Sync {
         fn name(&self) -> &'static str;
         fn sandbox_provider(&self) -> Box<dyn SandboxProvider>;
         fn quota_monitor(&self) -> Box<dyn QuotaMonitor>;
         fn telemetry_provider(&self) -> Box<dyn TelemetryProvider>;
         fn capabilities_matrix(&self) -> RuntimeCapabilitiesMatrix;
     }
     ```
2. **Matriz de Capacidades Tipadas (`RuntimeCapabilitiesMatrix`):**
   - Indicar con precisión el estado de cada capacidad en el entorno de ejecución:
     - `LandlockLSM`: Nativo / No soportado / Simulado.
     - `Seatbelt`: Nativo / No soportado.
     - `CgroupsV2`: Nativo / Emulado por process watchdog.
     - `EbpfSupervision`: Nativo (Linux) / Simulado (macOS).
     - `KvmHypervisor`: Hardware-assisted / Fallback a proceso confinado.
     - `WaylandDesktop`: Nativo / Headless / Web bridge.
3. **Implementaciones de Runtime:**
   - `LinuxRuntime`: Integra Landlock LSM, Cgroups v2, socket eBPF real y KVM.
   - `DarwinRuntime`: Integra Apple Seatbelt sandbox-exec, supervisor RSS por proceso y fallback seguro para eBPF.
   - `BareMetalRuntime`: Preparado para interactuar directamente con las syscalls del kernel propio de antOS.
4. **Comando de Diagnóstico `antos doctor` y `antos runtime info`:**
   - Comando CLI que audita el host: verifica versión del kernel, soporte de virtualización KVM / Hypervisor.framework, presencia de Landlock/Seatbelt, permisos de socket Wayland y estado de Ollama/LLMs.
   - Genera un informe visual claro en terminal con marcas de verificación verdes/amarillas.
5. **Pruebas y Verificación:**
   - Pruebas unitarias que validen la instanciación del runtime correcto según `cfg(target_os)` y la consistencia de la matriz de capacidades.

## Criterios de Aceptación
* Se implementa el trait `PlatformRuntime` y se eliminan las directivas condicionales dispersas sin orden en el demonio.
* Las capacidades de sandbox, cuotas y telemetría se despachan a través de la abstracción de plataforma.
* `antos doctor` diagnostica el estado del sistema host y reporta con precisión qué capacidades son nativas o simuladas.
* Todas las pruebas existentes de sandbox (Landlock en Linux, Seatbelt en macOS) se ejecutan a través de este runtime y pasan exitosamente.
