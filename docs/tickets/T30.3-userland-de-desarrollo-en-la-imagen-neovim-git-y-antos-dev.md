# T30.3 · Userland de Desarrollo en la Imagen: Neovim, Git, Terminal y `antos dev`

> **Estado:** 🔄 En Progreso
> **Fase:** Fase 30 (Escritorio antOS Linux — NixOS / Wayland, driver diario)
> **Fecha:** September 2026
> **Dependencias:** T30.1 (módulo de sesión), T20.1 (`antos dev` TUI con Neovim), T12.1 (`antos lsp`), T16.2 (`antpkg`), T25.x (`antos app` / Flatpak).

## Descripción

La imagen de antOS Linux debe traer, de fábrica y de forma declarativa, el
mínimo para trabajar: editor (Neovim con `antos-lsp`), Git, una terminal
Wayland, `antos dev` (`Super+W`), un gestor de ficheros y las tuberías de
`antpkg`/Flatpak listas para instalar el resto (navegador, IDEs). Hoy
`syso-paquetes.nix` sólo tiene `htop`.

## Alcance Técnico

1. **Conjunto base declarativo (`system/nixos/syso-paquetes.nix` o un módulo
   `services.antos.desktop.devTools`):**
   - Editor: `neovim` + configuración que autoconecta `antos-lsp`
     (`EDITOR`/`VISUAL` ya los fija T30.1); plugins mínimos vía `programs.neovim`
     de NixOS (LSP, treesitter, fzf).
   - Git + `gh` + `delta`; `direnv` + `nix-direnv`.
   - Terminal Wayland (`foot`), multiplexor (`tmux` o `zellij`), `ripgrep`,
     `fd`, `bat`, `jq`, `htop`, `fastfetch`.
   - Gestor de ficheros ligero (`pcmanfm` o `yazi` en la terminal).

2. **`antos dev` en la sesión:**
   - Atajo `Super+W` (ya en `rc.xml`, T13.0) lanza `antos dev` en la terminal
     configurada; verificar que el *layout* multi-panel (Neovim + monitor de
     agentes + diffs + VTE) arranca dentro de la sesión Wayland.
   - `antos-lsp` disponible en el `PATH` del sistema.

3. **`antpkg` / `antos app` operativos en la imagen:**
   - `antpkg` con su almacén CAS en `/var/lib/antos/...`; `flatpak` +
     `flathub` remoto preconfigurado (o documentado el `flatpak remote-add`).
   - Recetas `antpkg` para un navegador (Firefox) y un IDE (VS Code / Zed)
     instalables con un comando, inyectando `$ANTOS_WORKSPACE`.

4. **Documentación (`docs/manual-de-comandos.md`):** sección "Escritorio antOS
   Linux — herramientas incluidas" con la lista, cómo abrir `antos dev`, y cómo
   instalar navegador/IDE con `antpkg`/`antos app`.

## Criterios de Aceptación

- En la VM gráfica de T30.2: `nvim` abre con `antos-lsp` activo sobre un
  proyecto del workspace (diagnósticos/hover funcionan).
- `git`, `gh`, `foot`, `rg`, `fd`, `bat`, `jq` están en el `PATH` sin instalar
  nada a mano.
- `Super+W` abre `antos dev` con su *layout* completo dentro de la sesión
  Wayland.
- `antpkg install firefox` (o `antos app install …`) instala y lanza un
  navegador con el workspace inyectado.
- Todo declarado en Nix: reconstruir la imagen reproduce exactamente el mismo
  conjunto.
- `nixos-rebuild build` evalúa sin errores; `cargo check --workspace` sin
  regresión.
- `docs/manual-de-comandos.md` documenta el userland incluido.

## Estado de Verificación (September 2026)

**Implementado (`system/nixos/desktop.nix`):**

1. **Opción `services.antos.desktop.devTools`** (`bool`, por defecto `true`) y
   `services.antos.desktop.browser` (`nullOr package`, por defecto
   `pkgs.firefox`). El `config` del módulo pasa a `lib.mkMerge` de dos bloques:
   la sesión (T30.1) y el userland de desarrollo (`lib.mkIf cfg.devTools`).
2. **Neovim declarativo** (`programs.neovim`): `enable`, `defaultEditor`,
   `viAlias`/`vimAlias`, `configure.packages.antos.start` con
   `nvim-lspconfig` + `nvim-treesitter` (rust/python/nix/lua/markdown/bash/js/ts)
   + `telescope-nvim` + `plenary-nvim` + `fzf-lua`, y `customRC` que registra
   el *language server* `antos_lsp` con `cmd = { "antos", "lsp" }`.
   **No hay binario `antos-lsp` aparte**: es el subcomando `antos lsp` del CLI
   que aporta `antosd` (`system/antosd/src/cli/commands/dev.rs::cmd_lsp` →
   `crate::lsp::LspServer`).
3. **Git y CLI**: `gh`, `delta`, `programs.direnv` + `nix-direnv`, `tmux`,
   `ripgrep`, `fd`, `bat`, `jq`, `htop`, `fastfetch`, `yazi`, `wget`, `curl`.
4. **`services.flatpak.enable`** para `antos app` (el remoto `flathub` se
   añade en el primer arranque; documentado).
5. **Navegador**: `cfg.browser` (`firefox`) en `systemPackages` salvo `null`.
6. **Documentación**: `docs/manual-de-comandos.md` (Método 5, "Herramientas de
   desarrollo incluidas").

**Pruebas (contenedor `nixos/nix` sobre `podman`, aarch64-linux):**
