# T19.4 · Enriquecimiento del Equipo Multi-Agente antFlow y Asignación de Modelos por Rol

> **Estado:** ✅ Completado  
> **Fase:** Fase 19  
> **Fecha:** September 2026

## Descripción
Conectar el pipeline de ejecución del equipo multi-agente antFlow (`system/antosd/src/flow.rs`) con el subsistema Multi-LLM para que cada uno de los roles especializados (*Arquitecto 📐, Coder 💻, QA 🧪, Auditor 🛡️*) pueda generar planes reales, archivos de código en *worktrees* efímeros y reportes de auditoría utilizando modelos de IA reales. Permitir la configuración granular de modelos por rol (`antos agent config`), optimizando costes y capacidades (ej. razonamiento profundo con DeepSeek-R1 para Arquitectura, generación rápida de código con Qwen2.5-Coder para Coder, y validación veloz con Llama-3.3 en Groq para QA y Auditoría).

## Alcance Técnico
1. **Configuración de Modelos por Rol de Agente:**
   - Soporte en `llm_config.json` para mapear roles a combinaciones `<proveedor>:<modelo>`.
   - Comandos CLI:
     - `antos agent config`: Muestra la matriz actual de modelos asignados a cada rol.
     - `antos agent config --role coder --llm ollama:qwen2.5-coder`: Asigna un modelo específico al Coder.
     - `antos agent config --role architect --llm openrouter:deepseek/deepseek-r1:free`: Asigna un modelo de razonamiento al Arquitecto.
2. **Ejecución Real Guiada por LLM en `antFlow` (`system/antosd/src/flow.rs`):**
   - **Rol Arquitecto:** Analiza el ticket técnico recibido, desglosa los cambios requeridos y define los archivos a tocar.
   - **Rol Coder:** Escribe los archivos de código fuente y modificaciones en el *worktree* aislado de Git asignado a la tarea.
   - **Rol QA / Tester:** Ejecuta la suite de pruebas del proyecto (`cargo test` o `npm test`), y si hay fallos, solicita una ronda de corrección al Coder.
   - **Rol Auditor:** Genera un resumen de seguridad y auditoría verificando que no se expongan secretos ni se violen fronteras de sandbox.
3. **Consolidación y Presentación en HUD / Wayland:**
   - Exposición de los modelos utilizados en el historial de transiciones de la tarea (`FlowTransition`).
   - Visualización en `antos panel` y `antos agent status` del modelo que ejecutó cada fase.
4. **Pruebas y Verificación:**
   - Pruebas unitarias del pipeline de roles con inyección de planificadores mock y verificación de asignación por rol.

## Criterios de Aceptación
* El usuario puede configurar modelos independientes para cada rol de antFlow con `antos agent config`.
* La ejecución de un pipeline con `antos agent run <ticket_id> --auto` consulta el LLM correspondiente a cada rol y produce cambios en el worktree efímero.
* Los reportes de auditoría y transiciones reflejan con precisión el modelo de IA que intervino en cada etapa.
* `cargo test --workspace` pasa al 100% sin advertencias ni regresiones.
