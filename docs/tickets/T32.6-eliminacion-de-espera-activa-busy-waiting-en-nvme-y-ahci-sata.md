# T32.6 · Eliminación de Espera Activa (Busy-Waiting) en Controladores NVMe y AHCI SATA

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 32 (Auditoría y Optimización de Rendimiento del Sistema)
> **Prioridad:** 🟡 Media
> **Fecha:** September 2026
> **Dependencias:** T15.1 (motor de almacenamiento), T23.2 (planificador preemptivo).
> **Origen:** Auditoría de rendimiento de September 2026.

## Descripción

Los controladores de almacenamiento de bloque del kernel bare-metal implementan operaciones de I/O mediante bucles de sondeo activo cerrado (*tight polling / busy-wait*):

### 1. NVMe (`kernel/src/drivers/storage/nvme.rs`)
En `NvmeController::submit_io_command`:
```rust
let mut spins = 5_000_000;
loop {
    compiler_fence(Ordering::SeqCst);
    let cqe = core::ptr::read_volatile(cqe_ptr);
    let phase = (cqe.status & 1) != 0;
    let expected_phase = self.iocq_phase == 1;

    if phase == expected_phase {
        ...
        return Ok(());
    }

    core::hint::spin_loop();
    spins -= 1;
    if spins == 0 {
        return Err(NvmeError::ControllerTimeout);
    }
}
```
Cada transferencia de bloque de 4096 bytes gira hasta 5 millones de veces en la CPU ejecutando `spin_loop()`. Durante este tiempo, la CPU está al 100% de ocupación ejecutando instrucciones vacías.

### 2. AHCI SATA (`kernel/src/drivers/storage/ahci.rs`)
En `AhciDisk::execute_command`:
```rust
let mut wait_spins = 20_000_000;
while (core::ptr::read_volatile(&port.ci) & 1) != 0 {
    if (core::ptr::read_volatile(&port.is) & (1 << 30)) != 0 {
        return Err(AhciError::IoError);
    }
    core::hint::spin_loop();
    wait_spins -= 1;
    if wait_spins == 0 {
        return Err(AhciError::CommandTimeout);
    }
}
```
Cada comando ATA gira hasta 20 millones de veces comprobando el bit de emisión de comando en el registro de puerto.

En ambos controladores, los hilos que realizan lectura/escritura de archivos no ceden el procesador a otros hilos listos para ejecutar (`ready_queue`), monopolizando los cores del sistema durante las transferencias de disco.

## Alcance Técnico

1. **Cesión de CPU en Espera de I/O:**
   - Incorporar comprobación no bloqueante con cesión voluntaria de CPU (`yield` al planificador preemptivo) tras un número corto de giros iniciales para operaciones ultrarrápidas, permitiendo que otros hilos computen mientras el dispositivo DMA transfiere sectores.
2. **Soporte para Suspensión de Hilo por I/O:**
   - Enlazar con el estado de hilo `ThreadState::Blocked` del planificador (`task/scheduler.rs`), de modo que el hilo que espera la finalización de un comando de disco se suspenda y sea despertado por la interrupción de hardware (IRQ / MSI) del controlador PCI o por el temporizador de sondeo del planificador.
3. **Optimización de Tiempos de Expiración:**
   - Sustituir los contadores arbitrarios de ciclos (`spins = 20_000_000`) por temporización calibrada en base a los ticks del reloj del kernel (`crate::task::timer::ticks()`), garantizando timeouts predecibles independientemente de la frecuencia de reloj del procesador.

## Criterios de Aceptación

- [ ] Las operaciones de lectura y escritura en NVMe y AHCI SATA no consumen el 100% del tiempo de CPU cuando el controlador físico o emulado tarda en responder.
- [ ] Si hay otros hilos listos en `ready_queue`, el planificador conmuta hacia ellos durante la espera de operaciones de disco prolongadas.
- [ ] Los timeouts de disco se basan en tiempo transcurrido real (ticks de temporizador) y no en iteraciones de bucle no calibradas.
- [ ] La integridad de datos leídos y escritos en particiones GPT / USTAR se mantiene intacta en los tests de almacenamiento.
