# T30.7 · Arranque Acelerado de la VM Gráfica en macOS (HVF)

> **Estado:** ✅ Completado
> **Fase:** Fase 30 (antOS Linux · escritorio Wayland)
> **Prioridad:** 🟡 Media
> **Fecha:** September 2026
> **Dependencias:** T30.2 (VM gráfica e ISO), T30.6 (escritorio sobre Labwc —
> su hallazgo motiva este ticket).
> **Origen:** T30.6 dejó registrado que `system/arrancar-vm.sh --grafica`
> corre QEMU **dentro** del contenedor podman, sin KVM ni HVF, y que bajo TCG
> labwc no se sostiene (`libseat`/`logind` ping timeout, carrera con el KMS de
> `virtio-gpu`).

## Descripción

`system/arrancar-vm.sh --grafica` construye la VM en un contenedor y arranca
QEMU **ahí dentro**. En Apple Silicon ese Linux no tiene virtualización
anidada, así que no hay `/dev/kvm` → QEMU cae a **TCG** (emulación por
software). El escritorio Wayland en TCG es, además de lentísimo,
**inestable**: `greetd` entra en bucle de reinicio de la sesión.

La salida es ejecutar QEMU **en el host macOS** con **HVF**
(Hypervisor.framework): el invitado AArch64 va a velocidad casi nativa sobre
un host Apple Silicon y labwc arranca en segundos sin bucle. Para eso hace
falta una **imagen autónoma** (la ISO en vivo de antOS Linux, `.#iso`), no el
`system.build.vm` que usa `arrancar-vm.sh` (ese monta el store del anfitrión
y solo corre en Linux).

## Alcance Técnico

- **`system/arrancar-vm-macos.sh` (nuevo):**
  1. Construye `path:/src#iso` en el contenedor `nixos/nix` (no hace falta
     Nix en macOS), reutilizando el volumen `antos-nix-store`.
  2. Copia la ISO fuera del contenedor a `target/antos-linux-aarch64.iso`.
  3. Arranca `qemu-system-aarch64` **en el host** con
     `-accel hvf -cpu host -M virt`, firmware UEFI EDK2
     (`edk2-aarch64-code.fd` de la propia instalación de QEMU +
     un fichero de variables escribible que se crea la primera vez),
     `virtio-gpu-pci` + `-display cocoa`, entrada USB (`usb-tablet` =
     puntero absoluto), y la ISO como disco `virtio`.
  - Flags: `--rebuild` (fuerza reconstruir la ISO), `--build-only` (solo
    construye y copia), `--headless` (serie a `stdio`, sin ventana — para
    CI/depuración).
  - Comprobaciones: `uname -s = Darwin`, `qemu-system-aarch64` en el PATH,
    firmware EDK2 presente (`/opt/homebrew` o `/usr/local`).
- **`docs/guia-emulacion-utm-virtualbox.md`:** una sección corta que remite a
  este guion y al camino UTM equivalente.
- **No se toca `arrancar-vm.sh`** (sigue siendo el camino headless/serie por
  contenedor, válido para CI y para ver el arranque). Este guion es el
  complemento gráfico para macOS.

## Criterios de Aceptación

- `system/arrancar-vm-macos.sh --build-only` produce
  `target/antos-linux-aarch64.iso` a partir de `.#iso`.
- `system/arrancar-vm-macos.sh --headless` arranca la ISO en QEMU-HVF en el
  host y el kernel del invitado llega a montar el sistema (mensajes de
  arranque de NixOS por la consola serie), sin caer al bucle de `greetd`.
- El guion se niega con un mensaje claro si se ejecuta fuera de macOS o sin
  `qemu`/firmware.
- `arrancar-vm.sh` no cambia de comportamiento.

## Estado de Verificación

### 1. Lo implementado

- **`system/arrancar-vm-macos.sh` (nuevo, +x):** comprueba host
  (`uname -s = Darwin`, `qemu-system-aarch64`, `podman`, firmware EDK2 en
  `/opt/homebrew` o `/usr/local`); construye `path:/src#iso` en el contenedor
  `nixos/nix` si falta o con `--rebuild`; copia la ISO a
  `target/antos-linux-aarch64.iso`; crea `target/edk2-aarch64-vars.fd`
  (flash de 64 MiB) la primera vez; y `exec`uta `qemu-system-aarch64`
  **en el host** con `-accel hvf -cpu host -M virt -smp 4 -m 4096`, par
  `pflash` (code EDK2 `readonly` + vars escribible), `virtio-net` + `user`,
  la ISO como `if=virtio,media=cdrom`, y —en modo gráfico— `virtio-gpu-pci`
  + `-display cocoa` + `qemu-xhci`/`usb-kbd`/`usb-tablet`. Flags
  `--build-only`, `--headless`, `--rebuild`.
- **`docs/guia-emulacion-utm-virtualbox.md`:** recuadro «Vía corta» al inicio.
- `system/arrancar-vm.sh` **sin cambios**.

### 2. Verificación ejecutada (en la Mac Apple Silicon del entorno)

- `system/arrancar-vm-macos.sh --build-only`: ✅
  `target/antos-linux-aarch64.iso` — `ISO 9660 … 'ANTOS_LINUX' (bootable)`,
  **2.4 GB**. `nix build path:/src#iso` termina con
  `ISO image produced: 1242515 sectors`.
- `system/arrancar-vm-macos.sh --headless`: ✅ arranca en QEMU-HVF y en
  **~12 s** (marcas de tiempo del kernel) llega a sistema:

  ```
  UEFI firmware (edk2-stable202408) → BdsDxe: starting "UEFI Misc Device"
  GNU GRUB 2.12 → Booting 'NixOS 26.11.20260831.34ab990 Installer'
  ...
  antos[617]:   ✓ escritura fuera de lo declarado: la deniega el kernel
  antos[617]:   ✓ quota monitor: cgroups-v2 (Native)
  antos[617]:   ✓ telemetry: ebpf-lsm (Native)
  antos[617]: ✓ all diagnostics passed
  [  OK  ] Started antOS · demonio de intenciones (IPC).
  <<< Welcome to NixOS 26.11.20260831.34ab990 (aarch64) - ttyAMA0 >>>
  antos-live login: nixos (automatic login)
  ```

  Es decir: firmware UEFI → GRUB → kernel NixOS → `antos-doctor` pasa todos
  sus diagnósticos sobre Linux real (recinto Landlock, cgroups-v2, eBPF-LSM)
  → `antos.service` (el demonio de T31.18) arranca → consola de usuario. **Sin
  bucle de `greetd`**: con HVF el arranque es lo bastante rápido para que no
  salte el timeout de `libseat`/`logind` que sí mataba a labwc bajo TCG.
- El modo gráfico (`-display cocoa`) no se puede verificar desde una sesión
  sin pantalla; queda para comprobación visual (es la ruta que este ticket
  habilita).
- Guardas del host: el guion se niega con mensaje claro fuera de macOS o sin
  `qemu`/firmware (código directo, revisado).
