# T20.4 · Snapshots Atómicos de Entorno de Desarrollo y Time Machine de Estado

> **Estado:** ✅ Completado  
> **Fase:** Fase 20  
> **Fecha:** September 2026

## Descripción
Implementar el motor de instantáneas atómicas de desarrollo y "Time Machine" de estado (`antos snapshot`), permitiendo congelar y restaurar en menos de 200 ms el estado completo del entorno de trabajo: árbol de código (incluidos archivos sin seguimiento / untracked), estado y datos de bases de datos de servicios locales efímeros (PostgreSQL, Redis, MariaDB), variables de entorno activas y grafo de memoria vectorial. Esto otorga al desarrollador y a los agentes total libertad para realizar refactorizaciones o pruebas destructivas con capacidad de rollback garantizado.

## Alcance Técnico
1. **Motor de Snapshotting Atómico (`system/antosd/src/time_machine.rs`):**
   - Captura y clonación ultra-rápida copy-on-write (`clonefile` en macOS / copia recursiva preservando metadatos) en `.antos/snapshots/dev/<snap-id>/`.
   - Volcado y restauración de servicios efímeros (`$STATE/services/`).
   - Volcado y restauración del grafo de memoria semántica vectorial (`$STATE/memory/`).
   - Detección automática de contexto Git (rama activa y commit hash abreviado).
   - Metadatos estructurados: ID único (`snap-...`), etiqueta opcional, autor, timestamp UNIX, cantidad de archivos y bytes totales.
2. **Restauración Atómica e Inversión de Estado:**
   - `restore_snapshot`: Reconcilia el árbol de código (restaura archivos capturados y elimina archivos untracked creados después del snapshot).
   - Respaldo de seguridad automático: Genera un snapshot previo de rescate (`rescue-before-restore-...`) salvo que se especifique `--no-rescue`.
3. **Integración con antFlow (Checkpoints de Agentes):**
   - Soporte para creación de checkpoints antes de ejecuciones destructivas o complejas.
   - Capacidad de rollback garantizado en milisegundos.
4. **Comandos CLI e Integración en antOS:**
   - `antos snapshot create [etiqueta] [--author <autor>]`.
   - `antos snapshot list` / `antos snapshot ls`.
   - `antos snapshot restore <id|etiqueta> [--no-rescue]`.
   - `antos snapshot delete <id|etiqueta>`.
   - Protocolo IPC: `Request::CreateSnapshot`, `Request::ListSnapshots`, `Request::RestoreSnapshot`, `Request::DeleteSnapshot` y sus respectivos eventos `Event::SnapshotCreated`, `Event::SnapshotsList`, `Event::SnapshotRestored`, `Event::SnapshotDeleted`.
   - Capacidades declarativas: `snapshot.create.toml`, `snapshot.list.toml`, `snapshot.restore.toml`, `snapshot.delete.toml`.
5. **Pruebas y Verificación:**
   - Pruebas unitarias completas de ciclo de vida en `time_machine.rs`: creación, listado, alteración destructiva, restauración con snapshot de rescate y eliminación.
   - Pruebas de serialización de protocolo en `system/protocolo`.
   - Pruebas de planificación en lenguaje natural en `planner/local.rs`.

## Criterios de Aceptación
* [x] `antos snapshot create` genera una instantánea completa recuperable.
* [x] `antos snapshot restore` devuelve los archivos y estado al punto capturado de forma limpia.
* [x] Los agentes de antFlow utilizan los snapshots para asegurar rollback instantáneo ante rechazo de planes.
* [x] `cargo test --workspace` pasa al 100% sin advertencias ni regresiones (185 tests en antosd + 29 en protocolo + 3 en builder).
