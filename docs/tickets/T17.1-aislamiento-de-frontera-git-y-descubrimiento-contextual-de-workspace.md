# T17.1 · Aislamiento de Frontera Git y Descubrimiento Contextual de Workspace

> **Estado:** ⏳ Pendiente  
> **Fase:** Fase 17  
> **Fecha:** September 2026

## Descripción
Establecer un aislamiento estricto entre el repositorio del sistema operativo antOS y los proyectos ubicados en el espacio de trabajo del usuario (`$WORKSPACE`). Prevenir fugas de diffs y estados de Git mediante `GIT_CEILING_DIRECTORIES` y restringir el algoritmo `find_git_root` para que nunca desborde hacia el `.git` superior del sistema operativo cuando se inspecciona un directorio del workspace. Mejorar además `Ctx::discover` para soportar la ejecución de comandos `antos` desde subdirectorios de proyectos sin perder la localización del catálogo de capacidades y la raíz del sistema.

## Alcance Técnico
1. **Aislamiento de Frontera en `system/antosd/src/git.rs`:**
   - Modificar `find_git_root` para que no cruce hacia la raíz de antOS cuando el punto de inicio esté dentro de un workspace o proyecto hijo.
   - Envolver todas las invocaciones de `std::process::Command::new("git")` en antOS con `GIT_CEILING_DIRECTORIES` fijado en el directorio padre del workspace o en la raíz de antOS.
2. **Descubrimiento Contextual en `system/antosd/src/ctx.rs`:**
   - Soporte para descubrir la raíz de antOS y `caps_dir` ascendiendo en el árbol si el comando se invoca desde subcarpetas como `workspace/api-service`.
   - Detección del subproyecto activo relativo a `ctx.workspace`.
3. **Pruebas y Verificación:**
   - Tests unitarios que verifiquen que un directorio sin `.git` dentro de `workspace/` no hereda ni expone el `.git` del sistema operativo.
   - Pruebas de `Ctx::discover` ejecutadas desde rutas anidadas.

## Criterios de Aceptación
* `find_git_root` sobre cualquier directorio dentro de `workspace/` retorna `None` a menos que exista un `.git` propio en dicho subdirectorio o en `workspace/`.
* Ningún comando de Git ejecutado por `antosd` o la CLI muestra archivos pertenecientes al núcleo o sistema operativo antOS (`system/`, `kernel/`, `docs/`) cuando opera sobre `workspace`.
* `antos` puede invocarse desde subdirectorios de proyectos (ej. `cd workspace/api-service && antos diff`) resolviendo correctamente el contexto y las capacidades del sistema.
* 100% de compatibilidad con `cargo test --workspace`.
