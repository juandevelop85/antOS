# T17.3 · Inicialización y Gestión Declarativa de Proyectos Git en Workspace

> **Estado:** ⏳ Pendiente  
> **Fase:** Fase 17  
> **Fecha:** September 2026

## Descripción
Proveer comandos y capacidades declarativas para inicializar y gestionar repositorios Git dentro de los proyectos del desarrollador (`workspace/<proyecto>`), automatizando la creación de repositorios limpios con rama principal `main`, configuración de autor por defecto y `.gitignore` adaptado al stack tecnológico del proyecto (Rust, Node, Python, Go). Integrar esta inicialización de forma nativa en `project.scaffold`.

## Alcance Técnico
1. **Capacidad Declarativa `project.git_init.toml` en `system/capabilities/`:**
   - Parámetros: `project` (nombre o ruta del proyecto), `branch` (rama inicial por defecto `main`).
   - Inicialización atómica de repositorio Git aislado con `GIT_CEILING_DIRECTORIES`.
   - Generación de `.gitignore` plantilla según el lenguaje detectado en el proyecto.
2. **Integración con `project.scaffold` en `system/antosd/src/exec.rs`:**
   - Inicializar automáticamente el repositorio Git al crear un nuevo proyecto mediante `project.scaffold`.
3. **Subcomando CLI `antos project init <nombre>` / `antos git init [nombre]`:**
   - Facilidad de uso para que el desarrollador comience el control de versiones en sus proyectos con un solo comando.
4. **Pruebas y Verificación:**
   - Pruebas unitarias de inicialización de repositorios en directorios temporales y validación de `.gitignore` generado.

## Criterios de Aceptación
* `antos project init api-service` inicializa un repositorio Git aislado en `workspace/api-service` con rama `main` y `.gitignore`.
* Los proyectos creados con `project.scaffold` quedan listos para control de versiones sin requerir comandos adicionales.
* `antos diff` reconoce de inmediato los repositorios inicializados y muestra sus diffs correspondientes.
* 100% de compatibilidad con `cargo test --workspace`.
