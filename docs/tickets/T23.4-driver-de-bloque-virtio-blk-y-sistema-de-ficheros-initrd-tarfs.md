# T23.4 · Driver de Bloque VirtIO (`virtio-blk`) y Sistema de Ficheros Inicial Initrd/tarfs

> **Estado:** ⏳ Pendiente  
> **Fase:** Fase 23  
> **Fecha:** September 2026

## Descripción
Dotar al kernel de antOS de capacidad real de almacenamiento secundario y desacoplar la carga de ejecutables de espacio de usuario. En el diseño actual, el programa de usuario debe ser incrustado directamente dentro del código binario del kernel mediante la directiva `include_bytes!(env!("USER_BINARY"))`. Este ticket implementa un driver de dispositivo de bloque para `virtio-blk` (el estándar moderno de virtualización en QEMU y KVM), un analizador de imágenes ramdisk iniciales en formato tar estándar (USTAR / `tarfs`) y una capa de Sistema de Ficheros Virtual (VFS) mínima que permite cargar múltiples binarios y archivos de configuración en tiempo de ejecución.

## Alcance Técnico
1. **Detección y Configuración de Dispositivos VirtIO PCI / MMIO:**
   - Exploración del espacio de configuración PCI (Vendor ID `0x1AF4`, Device ID `0x1001` legacy o `0x1042` moderno).
   - Secuencia de negociación de características (*Feature Negotiation*) y establecimiento del bit `DRIVER_OK`.
   - Asignación y configuración de la cola circular (*Virtqueue*): tablas de descriptores de búfer (*Descriptor Table*), anillo de disponibles (*Available Ring*) y anillo de usados (*Used Ring*).
2. **Driver de Almacenamiento por Bloques (`VirtioBlock`):**
   - Estructura `VirtioBlockRequest` (tipo de operación: lectura/escritura, sector de 512 bytes de inicio, búfer de datos y byte de estado).
   - Funciones síncronas/asíncronas `read_blocks(lba: u64, buf: &mut [u8])` y `write_blocks(lba: u64, buf: &[u8])`.
   - Manejo de notificaciones vía MMIO / puerto de I/O (`Queue Notify`).
3. **Módulo de Disco en Memoria Ramdisk (`tarfs`):**
   - Soporte para imagen initramfs cargada en memoria RAM por el bootloader o leída desde el disco VirtIO.
   - Analizador de cabeceras USTAR de 512 bytes: extracción determinista de ruta (`path`), tamaño del archivo en base octal, tipo de archivo (`regular`, `directory`) y puntero a los datos contiguos.
4. **Capa VFS Básica del Kernel (`kernel/src/fs/`):**
   - Abstracciones unificadas `Inode`, `FileHandle` y operaciones fundamentales:
     - `vfs::open(path: &str) -> Result<FileHandle, FsError>`
     - `vfs::read(handle: &mut FileHandle, buf: &mut [u8]) -> Result<usize, FsError>`
     - `vfs::stat(path: &str) -> Result<FileInfo, FsError>`
5. **Desacoplamiento del Cargador ELF (`kernel/src/elf.rs`):**
   - Modificar la función `elf::load` para que acepte un lector o búfer cargado dinámicamente desde el VFS (ej. `/bin/init`, `/bin/shell`) en lugar de depender de `include_bytes!`.
6. **Pruebas y Verificación:**
   - Prueba de integración en QEMU arrancando con un disco virtio o imagen initrd adjunta y cargando dos ejecutables ELF distintos de forma secuencial.

## Criterios de Aceptación
* El driver `virtio-blk` se comunica con éxito con el dispositivo emulado de QEMU.
* El sistema de ficheros `tarfs` analiza correctamente el contenido de un archivo tar y permite consultar su índice de ficheros.
* El kernel carga programas de espacio de usuario directamente desde el sistema de archivos VFS sin requerir `include_bytes!`.
* Cero fallos de lectura, desalineaciones de memoria o panics durante la carga de bloques.
* `cargo test --workspace` compila y pasa sin errores.
