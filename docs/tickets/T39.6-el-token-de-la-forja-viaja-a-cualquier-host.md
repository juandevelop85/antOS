# T39.6 · El Token de la Forja Viaja a Cualquier Host

> **Estado:** ⏳ Pendiente

> **Prioridad:** 🟠 Alta
> **Fecha:** September 2026
> **Dependencias:** T21.2 (sincronización con forjas), T31.6 (bóveda).
> **Origen:** auditoría de seguridad de 2026-09-25.

## Descripción

[`forge.rs`](../../system/antosd/src/forge.rs) decide a qué API llamar
—y con qué token— a partir **del remote de git del repositorio**, que
controla quien escribió ese repositorio:

- `parse_remote_url` clasifica como GitLab cualquier host que **contenga**
  `gitlab` y como GitHub cualquiera que contenga `github`. Un remote
  `https://gitlab.atacante.com/x/y` recibe `GITLAB_TOKEN` en la cabecera
  `PRIVATE-TOKEN`; `github.atacante.com` sería tratado como GitHub.
- Los hosts que no encajan (`Generic`) reciben `FORGE_TOKEN` en
  `https://<host>/api/issues`.
- El token se pasa a `curl` como **argumento** (`-H "Authorization: token
  …"`), visible en `ps` y en `/proc/<pid>/cmdline` para cualquier usuario
  de la máquina mientras dura la petición.
- Si no hay remote, se usa `juandevelop85/antOS` como valor por defecto:
  un repositorio ajeno recibe peticiones autenticadas del usuario.

## Alcance Técnico

1. Cada token se asocia a un **host exacto**: `github.com` /
   `api.github.com` para `GITHUB_TOKEN`, `gitlab.com` para `GITLAB_TOKEN`,
   y hosts adicionales solo si el usuario los registra
   (`antos forge add-host <host> --token-key <clave>`), guardados en
   `$STATE`. Comparación exacta, no `contains`.
2. Sin host registrado: la petición se hace **sin** token (o no se hace).
3. Sustituir `curl` por `ureq` (ya dependencia del crate) para que el
   token nunca salga del proceso; si se mantiene `curl`, la cabecera va por
   `-H @-` desde stdin o un fichero `0600` temporal.
4. Eliminar el remote por defecto `juandevelop85/antOS`: sin remote, error
   claro.
5. Solo `https://` para peticiones con token.

## Criterios de Aceptación

- Test: `parse_remote_url("https://gitlab.evil.com/a/b")` no obtiene
  `GITLAB_TOKEN`.
- Test: `github.com.evil.com` no se trata como GitHub.
- Test: sin remote, `list_issues` no hace ninguna petición autenticada.
- Ningún argumento de proceso lanzado por `forge.rs` contiene el token.
