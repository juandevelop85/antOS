# T27.2 · Controlador PCIe ECAM y Host Controller USB 3.0 xHCI

> **Estado:** ✅ Completado  
> **Fase:** Fase 27 (Arranque Limine UEFI y Soporte de Plataformas Modernas)  
> **Fecha:** September 2026

## Descripción
En plataformas bare-metal modernas y máquinas virtuales UEFI contemporáneas (como VirtualBox 7 en macOS Apple Silicon o placas ARM64 como Raspberry Pi 4/5), los dispositivos de entrada legados (controladora de teclado PS/2 `i8042` y bus ISA) ya no existen físicamente. En su lugar, todos los periféricos de entrada (teclado, ratón, tablet) están conectados a una controladora de host **USB 3.0 xHCI** (*eXtensible Host Controller Interface*) expuesta sobre el bus **PCIe**.

Este ticket implementa el escáner de bus PCIe basado en el estándar ECAM (*Enhanced Configuration Access Mechanism*) y el driver del controlador de host xHCI en el kernel de antOS, permitiendo descubrir el hardware USB, configurar sus estructuras de DMA (Command Ring, Event Ring, DCBAA) y activar el host controller para la enumeración de puertos.

## Alcance Técnico

1. **Escáner PCIe ECAM (`kernel/src/drivers/pci/`):**
   - Mapeo de la ventana MMIO de configuración PCIe ECAM (`0xfeddc000` en AArch64 / rango especificado por ACPI/DTB).
   - Función de recorrido de buses (0..255), dispositivos (0..31) y funciones (0..7).
   - Lectura de cabeceras PCI Tipo 0:
     - Detección de Vendor ID, Device ID, Status y Command registers.
     - Filtrado de clase `0x0C` (*Serial Bus*), subclase `0x03` (*USB*), Prog-IF `0x30` (**xHCI**).
   - Lectura y asignación de BAR0 (memoria MMIO base del controlador xHCI).
   - Habilitación de Bus Master y Memory Space en el registro PCI Command (`0x0006`).
   - Mapeo de la base física de BAR0 en la MMU con atributos de dispositivo (`DEVICE_BLOCK_FLAGS`).

2. **Driver Host Controller xHCI (`kernel/src/drivers/usb/xhci/`):**
   - **Registros de Capacidad:**
     - `CAPLENGTH`: Longitud de cabecera para localizar registros operacionales.
     - `HCSPARAMS1`: Descubrimiento de `MaxSlots`, `MaxIntrs` y `MaxPorts`.
     - `DBOFF`: Desplazamiento del array de *Doorbells*.
     - `RTSOFF`: Desplazamiento de los registros de *Runtime*.
   - **Inicialización y Reset del Host:**
     - Esperar a que `USBSTS.CNR` (*Controller Not Ready*) sea 0.
     - Reset por software activando `USBCMD.HCRST`.
     - Configurar `CONFIG.MaxSlotsEn` con el número máximo de slots activos.
   - **Estructuras de Memoria DMA (Alineadas a 4 KiB):**
     - **DCBAA** (*Device Context Base Address Array*): Punteros a los Device Context de cada slot.
     - **Command Ring**: Anillo circular de 16-byte TRBs (*Transfer Request Blocks*) con ciclo de bit productor/consumidor.
     - **Event Ring & ERST**: Tabla de segmentos de anillo de eventos y puntero `ERDP` para recepción de eventos de hardware.
   - **Arranque:**
     - Poner a 1 el bit `USBCMD.RS` (*Run/Stop*) e inicializar el interrupter primario.

3. **Inspección de Puertos RootHub:**
   - Lectura de los registros `PORTSC` para cada puerto del RootHub.
   - Detección de conexión física (`PORTSC.CCS == 1`) y estado de reset del puerto.
   - Detección de velocidad de enlace (FullSpeed, LowSpeed, HighSpeed, SuperSpeed).

## Criterios de Aceptación
* El escáner PCIe descubre con éxito la controladora xHCI tanto en VirtualBox (`arm-pl011` / `usb-xhci`) como en hardware real o QEMU PCIe.
* BAR0 de xHCI se mapea correctamente en la tabla de páginas de la MMU sin generar fallos síncronos ni excepciones.
* El host xHCI se resetea y completa la inicialización pasando `USBSTS.CNR` a 0 y arrancando con `USBCMD.RS = 1`.
* Los registros `PORTSC` reportan correctamente los puertos con dispositivos conectados (como el teclado y ratón USB en los puertos 1 y 2 de VirtualBox).
* Pruebas unitarias de parsing de registros de configuración PCI y de empaquetado de TRBs xHCI pasan con `cargo test --workspace`.
