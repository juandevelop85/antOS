# T30.1 · Paquete Nix de `antos-barra` y Módulo de Sesión Wayland Declarativo

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 30 (Escritorio antOS Linux — NixOS / Wayland, driver diario)
> **Fecha:** Pendiente
> **Dependencias:** T13.0 (sesión Labwc y `system/desktop/`), T25.4 (lanzador de la barra), `system/nixos/` (módulo `services.antos`).

## Descripción

`system/nixos/` monta hoy sólo el demonio `antosd` (VM *headless*, `htop` y
poco más). La barra de escritorio (`system/barra`, GTK4 + `wlr-layer-shell`,
1352 líneas) **no tiene paquete Nix** (está excluida del workspace) y la
sesión Wayland de `system/desktop/` es un script suelto (`start-session.sh`
copia `rc.xml`/`autostart` a `~/.config/labwc`), no algo declarativo.

Este ticket empaqueta la barra con Nix y añade un módulo
`services.antos.desktop` que describe la sesión completa —compositor Labwc +
`antos-barra` + `antosd` + variables XDG + autologin a Wayland— de forma
declarativa, para que activarlo sea una línea del `configuration.nix`.

## Alcance Técnico

1. **Paquete Nix de `antos-barra` (`system/nixos/barra.nix`):**
   - `rustPlatform.buildRustPackage` sobre `system/barra` (workspace propio),
     con `nativeBuildInputs`/`buildInputs` de GTK4, `gtk4-layer-shell`, wayland,
     glib, pango, cairo, gdk-pixbuf.
   - Instala el binario `antos-barra` y el CSS (`system/barra/src/estilo.css`)
     en `$out/share/antos-barra/`.
   - Referenciado desde `overlay`/`paquete.nix` como `pkgs.antos-barra`.

2. **Módulo `services.antos.desktop` (`system/nixos/desktop.nix`):**
   - Opción `enable`, `compositor` (por defecto `pkgs.labwc`),
     `autologinUser`, `terminal` (por defecto `foot`), `editor`
     (por defecto `neovim`).
   - Cuando `enable`:
     - `environment.systemPackages`: compositor, `antos-barra`, `antosd`,
       terminal, `wl-clipboard`, `grim`/`slurp` (para `wlr-screencopy`),
       `xdg-desktop-portal-wlr`.
     - Genera `/etc/antos/desktop/rc.xml` y `/etc/antos/desktop/autostart` a
       partir de `system/desktop/` (los mismos atajos: `Super+Space`,
       `Super+A`, `Super+Return`, `Super+W`), y un fichero de sesión Wayland
       `antos.desktop` en `${pkgs.dbus}/share/wayland-sessions` equivalente.
     - `environment.sessionVariables` con el contenido de
       `system/desktop/environment` (`XDG_CURRENT_DESKTOP=antOS`,
       `GDK_BACKEND=wayland`, `EDITOR=nvim`, `ANTOS_COMPOSITOR=labwc`, …).
     - `services.greetd` (o autologin de `getty` + `exec labwc`) que arranca
       la sesión antOS para `autologinUser`.
     - `services.antos.enable = true` implícito (levanta `antosd`).
   - `autostart` lanza `antosd` (si no corre) y `antos-barra` como cliente
     layer-shell, igual que `system/desktop/autostart` pero con rutas del
     store.

3. **Integración con `system/nixos/configuracion.nix`:** añadir
   `services.antos.desktop.enable = true;` como opción comentada + documentada;
   `vm.nix` se resuelve en T30.2.

4. **Retrocompatibilidad:** `system/desktop/start-session.sh` sigue existiendo
   para lanzar la sesión sobre un Linux no-NixOS (dev), reusando los mismos
   `rc.xml`/`autostart`/`environment` que consume el módulo.

## Criterios de Aceptación

- `nix build` del paquete `antos-barra` produce un binario ejecutable con sus
  dependencias GTK4/Wayland resueltas.
- Un `configuration.nix` con `services.antos.desktop.enable = true` evalúa sin
  errores (`nixos-rebuild build`) e incluye el compositor, `antos-barra`,
  `antosd`, la terminal y el editor en el sistema.
- Los ficheros `rc.xml` / `autostart` / variables de entorno generados en
  `/etc/antos/desktop` coinciden en atajos y semántica con `system/desktop/`.
- `system/desktop/start-session.sh` sigue funcionando sobre un Linux con
  `labwc` en el PATH (sin regresión de T13.0).
- Documentado en `docs/manual-de-comandos.md` (Método 5) y en
  `docs/arquitectura.md`.
- `cargo build -p antos-barra` (en Linux) y `cargo check --workspace`
  (crates host) sin regresión.
