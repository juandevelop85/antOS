# T31.18 · El Módulo NixOS de antOS No Arranca el Demonio

> **Estado:** ✅ Completado
> **Fase:** Fase 31 (Auditoría de Código: Corrección y Endurecimiento)
> **Prioridad:** 🟠 Alta
> **Fecha:** September 2026
> **Dependencias:** T30.1 (módulo `services.antos.desktop`), T31.8 (socket IPC
> `0600`), T31.17 (la VM ya se construye y arranca al escritorio).
> **Origen:** Arrancar la VM gráfica de antOS Linux tras T31.17 — el escritorio
> aparece pero `antos-barra` no encuentra el demonio.

## Descripción

En la VM gráfica de antOS Linux el escritorio arranca (Labwc + `antos-barra`
anclada), pero la barra muestra en rojo:

```
no hay demonio antOS en /var/lib/antos/estado/antos.sock: Permission denied (os error 13)
Arráncalo en otra terminal con: antos demonio
```

Son **dos cosas**, encadenadas:

1. **El demonio no corre.** `system/nixos/module.nix` (`services.antos`)
   define **un solo** servicio systemd: `antos-doctor`, un `oneshot` que
   ejecuta `antos doctor` al arrancar. **No hay ningún
   `systemd.services.antos`** que ejecute `antos demonio` — el subcomando que
   hace `ipc::serve` y crea el socket (`cli/mod.rs`:
   `"demonio" => ipc::serve(ctx, catalog)`). Nada escucha en el socket.
   El texto del Método 5 del manual dice «antOS completamente integrado como
   demonio de sistema systemd»; el módulo del flake no lo cumple. (El
   `system/iso/live-image.nix` de T14.x sí tenía un `systemd.services.antosd`,
   pero apunta a un `/usr/local/bin/antosd` inexistente y no es lo que monta
   el flake actual — `iso.nix` usa `module.nix`.)

2. **El error es `Permission denied`, no «no existe».** `systemd.tmpfiles`
   crea el directorio de estado como `0700 root root`
   (`d /var/lib/antos/estado 0700 root root -`) y `antos-barra` corre como el
   usuario de autologin de `greetd` (`antos`). Ese usuario no puede ni entrar
   al directorio: `connect()` falla con `EACCES` antes de descubrir que no hay
   socket.

Y aunque se añadiera el servicio corriendo como `root`, seguiría sin
funcionar: el socket se crea **`0600`** a propósito (T31.8, endurecimiento
del IPC — no se debe relajar), así que **solo el usuario que lo crea puede
conectarse**. Para el escritorio, ese usuario tiene que ser el mismo que
corre la sesión Wayland.

## Alcance Técnico

- **`system/nixos/module.nix`:**
  - Nueva opción `services.antos.user` (por defecto `"root"`): el usuario bajo
    el que corre el demonio. Como el socket es `0600`, define quién puede
    hablarle.
  - Nuevo `systemd.services.antos`: `Type = "simple"`,
    `ExecStart = "${lib.getExe cfg.package} demonio"`,
    `User = cfg.user`, `environment = config.environment.variables`,
    `wantedBy = [ "multi-user.target" ]`,
    `after = [ "antos-doctor.service" "systemd-tmpfiles-setup.service" ]`,
    `Restart = "on-failure"`.
  - Las reglas de `tmpfiles` de `workspace` y `state` pasan a ser propiedad de
    `cfg.user` en vez de `root`, para que el demonio (ya no root) pueda crear
    el socket y escribir estado.
- **`system/nixos/desktop.nix`:** `services.antos.user = lib.mkDefault
  cfg.autologinUser`. Así, con el escritorio activado, el demonio corre como
  el usuario de la sesión y `antos-barra` (mismo usuario) llega al socket
  `0600`. Sin escritorio, `user` sigue siendo `root` y el comportamiento
  headless no cambia.
- **No se toca `system/antosd`.** `ipc::serve` ya limpia un socket huérfano
  antes de `bind` (`let _ = std::fs::remove_file(&path);`), así que un
  reinicio de la VM con el socket persistente en `/var/lib` no rompe el
  arranque.
- **Fuera de alcance, anotado:** correr el demonio como usuario normal deja
  sin delegación de cgroups v2 algunas capacidades de límites de recursos
  (T16.x); degradan, no rompen el escritorio. `antos doctor` sigue corriendo
  como `root` en su propio `oneshot`, sin cambios.

## Criterios de Aceptación

- En la VM gráfica: `systemctl status antos` → `active (running)`;

## Estado de Verificación

### 1. Los cambios

- `system/nixos/module.nix`:
  - Nueva opción `services.antos.user` (por defecto `"root"`).
  - Nuevo `systemd.services.antos`: `Type = simple`, `User = ${cfg.user}`,
    `ExecStart = ${lib.getExe cfg.package} demonio`,
    `wantedBy = [ "multi-user.target" ]`,
    `after = [ "antos-doctor.service" "systemd-tmpfiles-setup.service"
    "local-fs.target" ]`, `Restart = on-failure`, `RestartSec = 2`.
  - `systemd.tmpfiles.rules`: `workspace` y `state` pasan de
    `… root root -` a `… ${cfg.user} root -`.
- `system/nixos/desktop.nix`: `services.antos.user = lib.mkDefault
  cfg.autologinUser`.
- `system/antosd`: sin cambios.

  ficheros `.nix`, ningún crate de Rust.
