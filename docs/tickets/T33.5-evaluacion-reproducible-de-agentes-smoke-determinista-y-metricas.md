# T33.5 · Evaluación Reproducible de Agentes: Smoke Determinista y Métricas

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 33 (Agentes que construyen software)
> **Prioridad:** 🟡 Media
> **Dependencias:** T33.2, T33.3, T31.10 (CI verde como requisito),
> T22.x (bench e historial).
> **Origen:** Un runtime de agentes sin evaluación se degrada sin que nadie
> lo note: un cambio de prompt, de modelo o de toolset puede duplicar los
> pasos o dejar de pasar tests y nada en CI lo diría.

## Descripción

Dos niveles de evaluación, ambos declarativos y guardados en el repo:

1. **Smoke determinista (CI, siempre):** casos en `evals/agent/*.toml`
   con un proyecto de ejemplo (fixture), un objetivo y un **guion** del
   proveedor `fake` (T33.2). Verifica el *contrato* del runtime: orden de
   herramientas, validación, tiers, snapshots, journal, presupuesto,
   informe. Corre en `cargo test` y en el job `nix-build`.
2. **Evaluación con modelo (opcional, `antos eval agent --live`):** los
   mismos casos contra el proveedor configurado, con métricas por caso:
   pasos, tokens/coste, tiempo, tests en verde (sí/no), ficheros tocados
   fuera del plan, rechazos de validación. Resultados en
   `.antos/evals/<fecha>.json` y `antos eval diff` contra la ejecución
   anterior (reutiliza el enfoque de `bench.diff`, T22.x). Nunca en CI
   (clave y coste); sí documentado como paso previo a cambiar prompts o
   modelos por rol.

## Alcance Técnico

- **`evals/agent/`:** fixtures pequeños (un crate Rust con un test
  rojo; un proyecto Node con un test rojo) y casos `.toml` (`goal`,
  `toolset`, `budget`, `script` para `fake`, `expect` = herramientas
  esperadas, tests en verde, ficheros permitidos).
- **`system/antosd/src/agent/eval.rs`:** carga de casos, ejecución con
  `fake` o proveedor real, cálculo de métricas, diff contra la ejecución
  anterior con umbrales (p. ej. +30 % pasos o cualquier test en rojo →
  regresión).
- **CLI:** `antos eval agent [--live] [--case <nombre>]`, `antos eval diff`.
- **CI (`.github/workflows/ci.yml`):** job que ejecuta el smoke `fake`.
- **Docs:** `docs/manual-de-comandos.md` (sección de agentes: cómo
  configurar proveedor y modelos por rol, cómo evaluar antes de cambiar
  prompts).

## Criterios de Aceptación

- `antos eval agent` (sin `--live`) pasa en CI con todos los casos y
  falla si se rompe el orden de herramientas, la validación o el
  presupuesto (test que muta un caso y comprueba el fallo).
- `antos eval agent --live` con clave real produce el JSON de métricas y
  `antos eval diff` señala una regresión inyectada (test con dos JSON de
  ejemplo).
- El manual documenta el flujo completo: proveedor → modelos por rol →
  `antos agent do` → `antos agent run <ticket> --auto` → aprobación →
  PR, y cómo evaluar.
- `cargo test --workspace` y CI en verde.
