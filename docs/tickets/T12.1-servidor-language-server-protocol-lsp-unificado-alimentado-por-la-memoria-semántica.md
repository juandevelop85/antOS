# T12.1 · Servidor Language Server Protocol (LSP) Unificado Alimentado por la Memoria Semántica

> **Estado:** ⏳ Pendiente  
> **Fase:** Fase 12  
> **Fecha:** September 2026

## Descripción
Implementación de un servidor LSP (`Language Server Protocol`) embebido en `antosd` que expone autocompletado inteligente, saltos a definiciones, referencias cruzadas y diagnósticos a cualquier editor externo (VS Code, Neovim, Helix, Emacs) directamente desde la base vectorial y el grafo de contexto de antOS.

## Alcance Técnico
1. **Servidor LSP Embebido (`system/antosd/src/lsp/`):**
   - Soporte para transporte stdio y TCP / socket UNIX.
   - Implementación de capacidades LSP estándar:
     - `textDocument/completion`: Completado semántico acelerado por el contexto de tickets y memoria local.
     - `textDocument/definition` & `references`: Resolución inmediata vía `ContextGraph`.
     - `textDocument/hover`: Documentación enriquecida y relación con especificaciones activas.
2. **Sincronización con Editores:**
   - Plugin/configuración mínima para VS Code, Neovim (`lspconfig`) y Helix.
3. **Capacidades Declarativas:**
   - `lsp.start`: Inicia el servidor LSP en modo stdio o socket.
   - `lsp.status`: Diagnóstico de conexiones de editores activas.
4. **Comandos CLI e Integración en antOS:**
   - `antos lsp`: Inicia el servidor LSP sobre stdio para integración en editores.
   - `antos lsp config <editor>`: Imprime el fragmento de configuración para el editor indicado.
5. **Pruebas y Verificación:**
   - Pruebas unitarias de parsing y respuesta a mensajes JSON-RPC de LSP (`initialize`, `completion`).
   - Mock de consulta semántica de definiciones.

## Criterios de Aceptación
* Editores externos pueden conectarse mediante LSP y recibir diagnósticos y completado semántico.
* `cargo test --workspace` pasa al 100% sin advertencias.
* Nomenclatura e identificadores en Rust 100% en inglés.
