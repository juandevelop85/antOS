# T28.7 · Paridad de Display: virtio-gpu-pci, ramfb y Cadena de Fallback de Framebuffer

> **Estado:** 🔲 Pendiente
> **Fase:** Fase 28 (Periféricos Completos y Robustez de Plataforma Bare-Metal)
> **Fecha:** —
> **Dependencias:** **T28.2** (bus PCIe) para `virtio-gpu-pci`. El resto es independiente.

## Descripción

El descubrimiento de framebuffer en AArch64 (`kernel/src/main.rs`) solo cubre: GOP de Limine (ruta UEFI), nodo DTB `simple-framebuffer`, y escaneo **MMIO** de VirtIO-GPU. Bajo QEMU `-M virt` con arranque directo (`-kernel`) ninguna de las tres se cumple de forma fiable y la ventana queda **negra**, aunque el kernel esté vivo por serie. Falta soporte de **virtio-gpu-pci** y de **ramfb** (fw_cfg), que son las formas más habituales de tener pantalla en QEMU/UTM sin UEFI.

Este ticket lleva el descubrimiento de display a paridad con el de entrada: varias fuentes, cadena de *fallback* ordenada y un log que explica qué se usó y por qué.

## Alcance Técnico

1. **VirtIO-GPU sobre PCIe (`kernel/src/arch/aarch64/virtio_gpu.rs` + `virtio_gpu_pci.rs` nuevo, o extensión):**
   - Detectar `virtio-gpu-pci` (`vendor 0x1AF4`, `device 0x1050`) en `scan_pci_bus` (requiere **T28.2**).
   - Transporte VirtIO **moderno** sobre PCIe: *capabilities* `VIRTIO_PCI_CAP_COMMON_CFG` / `NOTIFY_CFG` / `ISR_CFG` / `DEVICE_CFG`, localizadas por BAR + offset.
   - Reutilizar la lógica de comandos 2D existente (`RESOURCE_CREATE_2D`, `SET_SCANOUT`, `TRANSFER_TO_HOST_2D`, `RESOURCE_FLUSH`).

2. **ramfb / fw_cfg (`kernel/src/arch/aarch64/fw_cfg.rs`, nuevo):**
   - Driver fw_cfg MMIO (`-M virt`: registros en `0x0902_0000`), interfaz DMA.
   - Buscar el fichero `etc/ramfb` en el directorio fw_cfg; escribir `struct RAMFBCfg` (`addr` big-endian, `fourcc`, `flags`, `width`, `height`, `stride`) apuntando a un framebuffer lineal reservado en RAM del kernel.
   - Exponerlo a `console::init_raw` como framebuffer directo.

3. **Cadena de *fallback* (`kernel/src/main.rs`, `kmain_arm64`):**
   - Orden: **GOP Limine → DTB `simple-framebuffer` → VirtIO-GPU MMIO → VirtIO-GPU PCIe → ramfb → headless (solo serie)**.
   - Log explícito de la fuente elegida y del motivo de fallo de las anteriores.

4. **DTB (`kernel/src/arch/aarch64/dtb.rs`):**
   - Parseo correcto del nodo `framebuffer` / `simple-framebuffer` (formato de píxel, `stride`, `reg` = addr+size) y del nodo `fw-cfg`.

## Criterios de Aceptación

- `qemu-system-aarch64 -M virt -kernel … -device virtio-gpu-pci -display cocoa`: el Desktop Shell se pinta (hoy negro).
- `qemu-system-aarch64 -M virt -kernel … -device ramfb -display cocoa`: el Desktop Shell se pinta.
- UTM Método B (imagen UEFI) sigue pintando por GOP de Limine, sin regresión.
- El log de arranque lista la cadena de *fallback* intentada y la fuente final de framebuffer.
- `crate::console::resolution()` devuelve la resolución real en los tres caminos (MMIO, PCIe, ramfb).
- Pruebas unitarias del parser de *capabilities* VirtIO-PCI y del encoder de `RAMFBCfg` pasan con `cargo test --workspace`.
