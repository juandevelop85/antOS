# T18.4 · Llamadas al Sistema (SVC) en AArch64 y Generación de Imágenes UEFI (BOOTAA64.EFI)

> **Estado:** ⏳ Pendiente  
> **Fase:** Fase 18  
> **Fecha:** September 2026

## Descripción
Implementar el mecanismo de transición a espacio de usuario (*EL0*) y despacho de llamadas al sistema mediante la instrucción `svc #0` para AArch64. Actualizar el crate generador de imágenes de arranque (`builder/`) para soportar la creación de imágenes de disco arrancables bajo el estándar UEFI (partición GPT con EFI System Partition FAT32) empaquetando el binario `/EFI/BOOT/BOOTAA64.EFI` para QEMU o hardware real (ej. Apple Silicon con m1n1/U-Boot o Raspberry Pi 4/5), y documentar el flujo de ejecución en el manual de comandos.

## Alcance Técnico
1. **Llamadas al Sistema y Modo Usuario en `kernel/src/arch/aarch64/syscall.rs`:**
   - Intercepción de la excepción síncrona provocada por la instrucción `svc #0` (código de excepción `ESR_EL1.EC == 0b010101`).
   - Mapeo de argumentos de llamada al sistema según la convención ABI de AArch64 (número de syscall en `x8`, argumentos en `x0` a `x5`).
   - Retorno a nivel de excepción menor (*EL0*) mediante la instrucción `eret` tras configurar `SPSR_EL1` y `ELR_EL1`.
2. **Generador de Imágenes UEFI Multi-Arquitectura en `builder/`:**
   - Ampliar `builder/src/main.rs` para aceptar un flag de arquitectura (`--arch x86_64` o `--arch aarch64`).
   - Generación de estructura de disco con tabla de particiones GPT y partición ESP (FAT32).
   - Generación del archivo `/EFI/BOOT/BOOTAA64.EFI` (o empaquetado del kernel para arranque directo Limine / UEFI).
   - Soporte para generar tanto `.img` de disco como `.iso` híbrida para AArch64.
3. **Automatización y Scripts de Prueba:**
   - Script de prueba / subcomando `antos vm run --arch aarch64` o comando guiado en documentación para lanzar QEMU ARM64.
4. **Pruebas y Verificación:**
   - Prueba unitaria y de compilación de `builder` para la generación de la estructura EFI.
   - Ejecución de un binario de prueba en espacio de usuario invocando una syscall en el kernel AArch64 y verificando la respuesta por el puerto serie PL011.

## Criterios de Aceptación
* El kernel en AArch64 captura la instrucción `svc #0`, ejecuta la syscall y regresa a espacio de usuario sin corromper la pila ni los registros.
* `builder` puede generar una imagen de disco UEFI con el binario `BOOTAA64.EFI` correspondiente a AArch64.
* La imagen generada arranca en QEMU AArch64 con firmware UEFI (`QEMU_EFI.fd`).
* 100% de compatibilidad con `cargo test --workspace`.
