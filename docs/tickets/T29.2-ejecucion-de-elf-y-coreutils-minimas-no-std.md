# T29.2 · Ejecución de ELF Externos y Coreutils Mínimas `no_std`

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 29 (Shell Bare-Metal Decente — vía de I+D soberana)
> **Fecha:** Pendiente
> **Dependencias:** T26.4 (cargador ELF64 e initramfs), T26.5 (`libantos`), T29.1 (framework de comandos).

## Descripción

El shell soberano (`user/src/main.rs`, `antos-init`, PID 1 en EL0) no puede
ejecutar programas: `SYS_SPAWN` existe (T22.5/T23.5) pero no recibe `argv` y el
shell no lo usa. Además `/bin/sh`, `/bin/parted`, `/bin/mkfs.ext4` del
initramfs son ficheros de texto de ~45 bytes (relleno de T24.2).

Este ticket cierra el ciclo mínimo: `SYS_SPAWN` con `argv`, `SYS_WAITPID` con
código de salida, resolución tipo `PATH` en `/bin`·`/sbin`, y un **conjunto
reducido** de coreutils `no_std` reales para que el shell bare-metal sea
utilizable. (El bare-metal es una vía de I+D en paralelo; el escritorio de uso
diario es la Fase 30. Por eso el alcance es deliberadamente pequeño.)

## Alcance Técnico

1. **ABI del kernel (`kernel/src/syscall/`):**
   - `SYS_SPAWN` recibe `ptr_path`, `len_path`, `ptr_argv`, `argc` (`argv` =
     array de `(ptr, len)` en memoria de usuario). `argc == 0` = comportamiento
     actual (sin regresión de PID 1).
   - El kernel copia y valida `argv` (rango de punteros, tamaño máximo por
     argumento y total) y lo deja en la pila inicial del hijo según el contrato
     ABI de `libantos` (`argc`, `argv[]`, `NULL`).
   - `SYS_WAITPID` devuelve `Ok(exit_code_i32)` del hijo, error si el PID no es
     hijo. Sin `unwrap`/`expect`.
   - Syscalls de escritura de VFS sobre el `tarfs` en RAM:
     `SYS_FS_WRITEFILE`, `SYS_FS_MKDIR`, `SYS_FS_UNLINK`.
   - `SYS_REBOOT` con modo `reboot`/`halt` (AArch64: PSCI `SYSTEM_RESET`/
     `SYSTEM_OFF`; x86_64: reset ACPI o triple *fault*).
   - Tabla ABI actualizada en `docs/manual-de-comandos.md` §E.

2. **`libantos` (`user/libantos`):**
   - Lectura de `argc`/`argv` en el `_start` del runtime de usuario.
   - `spawn(path, args) -> Result<Pid, _>`, `wait(pid) -> Result<i32, _>`,
     `run(path, args) -> Result<i32, _>`.

3. **Shell (`user/src/main.rs` + registro de T29.1):**
   - Si el nombre no es *builtin*: buscar `/bin/<n>` y luego `/sbin/<n>`; si es
     ELF, `libantos::run(path, argv)`; propagar el código de salida a `$?`.
   - Errores diferenciados: `comando no encontrado` (127), `no es un
     ejecutable` (126), `fallo al lanzar` (≠ 0). Nada de pánicos.

4. **Coreutils `no_std` (`user/coreutils`, un *multicall* enlazado como varios
   nombres en `/bin`):** conjunto reducido —
   `echo`, `pwd`, `mkdir`, `rm`, `touch`, `env`, `uptime`, `free`, `clear`,
   `reboot`, `halt`, `true`, `false`.
   Cada una: parseo con `shell::args` (T29.1), código de salida coherente.

5. **Builtins del shell** (deben mutar el proceso del shell):
   `cd [ruta]` (actualiza `cwd`), `pwd`, `exit [code]`, `echo` con expansión
   de `$?` y `$VAR` básicas.

6. **Empaquetado (`builder`):** compila `user/coreutils` para el target de la
   imagen y coloca cada nombre en `/bin` del `initrd.tar` embebido; reemplaza
   los *stubs* de texto.

## Criterios de Aceptación

- Desde `antos>`: `echo hola mundo`, `pwd`, `cd /etc && cat os-release`,
  `mkdir /tmp/x`, `touch /tmp/x/a`, `rm /tmp/x/a`, `free`, `uptime`, `clear`
  funcionan con comportamiento POSIX razonable.
- `echo $?` refleja el código de salida del último comando (0 tras éxito,
  ≠ 0 tras `rm /no/existe`).
- Un binario de prueba `hello a b` imprime `argv = [hello, a, b]` y su código
  de salida llega al shell.
- `reboot` y `halt` reinician/detienen la VM limpiamente en QEMU `-M virt`
  (AArch64) y x86_64.
- `SYS_SPAWN` con `argc == 0` no regresiona el arranque de PID 1.
- `/bin/echo`, `/bin/pwd`, … son ELF reales, no *stubs*.
- Tests puros: *round-trip* de codificación de `argv` (ptr/len ↔ `Vec<String>`),
  resolución de rutas `/bin`→`/sbin`, parseo de flags de cada utilidad.
- `system/run-arm.sh --test` ejecuta `echo antos-ok` y verifica el eco.
- `cargo check --workspace`, `cargo build` del kernel y de `user/coreutils`
  para ambos targets, `cargo clippy` sin regresión.
- `docs/manual-de-comandos.md` §E lista las coreutils y las nuevas syscalls.
