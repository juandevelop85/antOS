# T35.3 · `test.run` por Stack, Verificación del Andamio y `project.scaffold` en el Toolset del Agente

> **Estado:** ✅ Completado
> **Fase:** Fase 35 (Proyectos por intención)
> **Prioridad:** 🟡 Media
> **Fecha:** September 2026
> **Dependencias:** T35.1, T35.2, T33.2/T34.4 (toolsets del agente), T33.5
> (evaluación reproducible).
> **Origen:** Con T35.1 y T35.2 el proyecto existe e instala; falta cerrar
> el ciclo: que antOS **compruebe** que lo que creó funciona, que el resto
> del sistema (`test.run`, `ci`, `env`) deje de adivinar el stack mirando
> qué fichero existe (`Cargo.toml`/`package.json`/`pyproject.toml`, tres
> copias del mismo `if` en `exec/fs.rs`, `ci.rs` y `env.rs`), y que un
> agente pueda encadenar «crea un proyecto X y añade Y» en un solo run.

## Descripción

### 1. Un solo lugar que sabe qué es cada proyecto

`.antos/project.toml` (T35.1) es la fuente de verdad del stack de un
proyecto. `test.run`, `ci.run` y `EnvEngine::detect_stack` lo leen
**primero**; si no existe (proyecto no creado por antOS), caen a la
detección por ficheros de hoy, y `antos project adopt <dir>` (nuevo
subcomando pequeño) escribe el `project.toml` a partir de esa detección
para que deje de adivinarse. `test.run` deja de tener el comando de test
codificado por lenguaje: usa `commands.test` del stack, con el mismo
`filter` (`--`/`-k` según gestor, declarado en el stack:
`test_filter_flag`).

### 2. Verificación del andamio

Al terminar `project.scaffold` + `project.run install`, la intención
añade un tercer paso `test.run` sobre el proyecto y el resultado del
conjunto dice, con las palabras justas: «proyecto antostest creado (nestjs),
dependencias instaladas, `npm test` en verde (1 test)». Si el test del
stack falla, el andamio **no** se da por bueno: se muestra la salida, el
snapshot permite `antos undo`, y el catálogo tiene un problema que se
arregla en el TOML (por eso cada stack lleva un test que pasa, T35.1).

### 3. El agente crea proyectos

`project.scaffold` y `project.run` entran en `DEFAULT_TOOLSET` del agente
(el completo; el compacto de modelos pequeños no: un 7B con el andamio
delante se pierde, y para él está la intención). Con eso `antos agent do
"crea un proyecto fastapi llamado api y añade un endpoint /health que
devuelva ok"` es un solo run: scaffold → install → patch → test.run →
finalizar, cada paso con su confirmación y su snapshot. El `AgentReport`
lista el proyecto creado.

### 4. Medir

Caso nuevo en `evals/agent/` (`scaffold-and-extend`, `live = true`,
`requires = ["node","npm"]`): objetivo «crea un proyecto typescript
llamado demo y haz que `npm test` pase con un test de suma»; expectativa:
`project.scaffold`, `project.run`, al menos un `fs.patch`/`fs.write`,
`test.run`, `finalizar`, tests en verde, escrituras solo bajo `demo/`.
Determinista con `fake` en CI; `--live --repeat 5` en el nocturno.

## Alcance Técnico

- **`stacks.rs`:** `ProjectManifest` (lectura/escritura de
  `.antos/project.toml`), `detect_or_adopt`.
- **`exec/fs.rs::run_tests`**, **`ci.rs`**, **`env.rs`:** consultan el
  manifiesto antes de la detección por ficheros; la detección por ficheros
  queda en una sola función compartida.
- **CLI:** `antos project adopt <dir>`, `antos project info <name>`
  (stack, comandos, puerto).
- **`planner/local`:** tercer paso `test.run` en la intención de crear.
- **`agent/tools.rs`:** `DEFAULT_TOOLSET` + `project.scaffold`,
  `project.run`; `roles.rs`: el Coder los recibe en el toolset completo.
- **`evals/agent/scaffold-and-extend.toml`** + fixture vacío.
- **Docs:** manual (§Proyectos completo: pedir, verificar, extender,
  adoptar), `docs/arquitectura.md`.

## Criterios de Aceptación

- `antos -y "crea un proyecto en nestjs llamado antostest"` termina con
  el mensaje de verificación y `npm test` en verde; con un stack cuyo test
  falla a propósito (test), el resultado lo dice y `antos undo` deja el
  workspace como estaba.
- `test.run` en un proyecto con `.antos/project.toml` usa `commands.test`
  del stack (test con un stack de prueba cuyo comando de test es distinto
  del adivinado); sin manifiesto, funciona como hoy (tests existentes en
  verde); `antos project adopt` escribe el manifiesto correcto para un
  `Cargo.toml`/`package.json`/`pyproject.toml`/`go.mod` (test).
- `antos agent do "crea un proyecto typescript llamado demo y …"` con
  Claude o un modelo local ≥ 7B llega a `Finished` con el proyecto creado,
  el test en verde y todas las escrituras bajo `demo/` (caso de evaluación
  en verde con `fake`; medido `--live --repeat 5` y anotado).
- El toolset compacto **no** incluye `project.*` (test).
- `cargo test --workspace`, clippy `-D warnings`, `fmt`; CI verde.

## Fuera de Alcance

- Servir el proyecto (`dev`) como servicio con puerto y URL en la barra.
- Plantillas de despliegue (Docker, Nix package del proyecto).

## Estado de Verificación

### 1. Los cambios

- **`stacks.rs`:** `ProjectManifest::{load, detect, load_or_detect, save,
  test_argv}`, `detect_language_by_files` (la **única** copia de la
  heurística: `exec/fs.rs::detect_project_language`, `env.rs::detect_stack`
  y `ci.rs::load_pipeline` la usan a través del manifiesto), `Commands.
  test_filter` (`{{filter}}`; declarado en los nueve stacks), `network` en
  el manifiesto.
- **`exec/fs.rs::run_tests`:** el `commands.test` del manifiesto (validado
  por lista blanca) antes de la detección; **`ci.rs`:**
  `pipeline_from_manifest` (security → install → build → test);
  **`env.rs`:** perfil desde el manifiesto.
- **`project.run verify`:** mismo comando que `test`, pero rojo = fallo del
  paso. El planificador propone `scaffold` → `install` → `verify` («sin
  verificar» / «sin instalar» lo acortan); la sesión revierte el andamio si
  falla (probado con un stack roto vía `ANTOS_STACKS`).
- **CLI:** `antos project adopt <dir>`, `antos project info <dir>`,
  `antos project stacks`.
- **Agente:** `project.scaffold` y `project.run` en `DEFAULT_TOOLSET`,
  `EDITING` **y en los compactos** (decisión por medida, abajo); un
  `--tools`/`toolset` explícito desactiva la sustitución por compacto.
- **Runtime (lo que la medida destapó):** el corte de bucle cuenta la misma
  llamada fallida en todo el run (no solo seguidas): el patrón real es
  `fs.read` → `fs.patch` ✗ → `fs.read` → mismo `fs.patch` ✗…; y antes de
  cortar como `Looping` se pide el cierre tipado (`structured_finish`,
  ahora helper común con el caso de prosa): a menudo el trabajo ya estaba
  hecho y el modelo se atascaba en un parche que ya no aplicaba.
- **Eval:** `evals/agent/scaffold-and-extend.toml` (+ fixture `empty`),
  `Expectation.tests_dir`, `files_allowed` con prefijo `dir/`.
- **Docs:** manual §4.1, arquitectura §10, `evals/agent/README.md`.

### 2. Medido (Mac, `qwen2.5-coder:7b`, `--live --repeat 5`)

| Configuración | `scaffold-and-extend` | Rust «arregla el test» |

| Compacto sin `project.*` | 0/3 (no puede crear) | — |

`fs.patch` intercalando `fs.read` hasta agotar los 20 pasos. Node sigue en
0/5 (ahora lo corta `looping`, antes el presupuesto): mismo motivo que en
T34.4.
