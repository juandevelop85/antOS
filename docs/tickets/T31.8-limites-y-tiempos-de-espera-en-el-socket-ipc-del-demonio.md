# T31.8 · Límites y Tiempos de Espera en el Socket IPC del Demonio

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 31 (Auditoría de Código: Corrección y Endurecimiento)
> **Prioridad:** 🟡 Media
> **Fecha:** September 2026
> **Dependencias:** T22.1 (modularización de `antosd`), T4.1 (barra de intenciones).
> **Origen:** Auditoría de código de September 2026.

## Descripción

`system/antosd/src/ipc.rs` atiende el socket Unix por el que hablan el CLI y la
barra Wayland. La cabecera del módulo dice: «El socket vive en el directorio de
estado con permisos 0600. Esa es hoy [la frontera]». Esa frontera tiene tres
grietas.

### Defecto 1 · Lectura de línea sin techo

`receive` (`ipc.rs:62-69`) usa `BufRead::read_line` sobre un `BufReader` sin
límite:

```rust
let mut line = String::new();
if source.read_line(&mut line)? == 0 {
    return Ok(None);
}
```

Un cliente que envíe bytes sin `\n` hace crecer la cadena hasta agotar la
memoria del demonio. El formato es una línea de JSON por mensaje, así que basta
envolver el lector en `Read::take(MAX)` y responder con un error de protocolo al
superarlo.

### Defecto 2 · Sin tiempos de espera y con atención estrictamente serial

`servir` (`ipc.rs:133-148`) atiende una conexión cada vez, y el comentario
explica bien por qué: dos intenciones mutando el mismo espacio de trabajo
producirían diffs que no describen el resultado. La serialización es correcta;
lo que falta es un tiempo de espera. Sin `set_read_timeout`, un cliente que
conecta y no envía nada bloquea el bucle **para todos los demás clientes**,
indefinidamente. Con permisos `0600` el atacante tiene que ser el propio
usuario, así que no es una escalada, pero sí un bloqueo trivial y accidental:
una barra Wayland colgada deja el CLI inservible.

### Defecto 3 · Ventana entre `bind` y `chmod`

`ipc.rs:123-125`:

```rust
let listener = UnixListener::bind(&path)...;
std::fs::set_permissions(&path, std::fs::Permissions::from_mode(0o600))?;
```

Entre las dos llamadas el socket existe con los permisos que dicte la `umask`.
En un directorio de estado compartido, otro usuario local puede conectarse en
esa ventana. Se cierra fijando la `umask` antes del `bind` y restaurándola
después, o creando el socket dentro de un directorio ya restringido a `0700`.

### Defecto 4 · Marca `syso` en la salida

`ipc.rs:129` sigue imprimiendo `syso · demonio escuchando en`, pese a que T0.1
dio por cerrado el renombrado. Se aborda de forma completa en T31.11.

## Alcance Técnico

1. Acotar el mensaje con `take(MAX_MESSAGE_BYTES)` y devolver un `Event::Error`
   descriptivo cuando se exceda, sin cerrar el demonio.
2. Aplicar `set_read_timeout` y `set_write_timeout` a cada `UnixStream`
   aceptado, y registrar en la bitácora las conexiones abandonadas.
3. Restringir el directorio de estado a `0700` y crear el socket dentro, o
   ajustar la `umask` alrededor del `bind`.
4. Documentar en la cabecera del módulo que la serialización de conexiones es
   deliberada, para que nadie la «arregle» convirtiéndola en concurrente.

## Criterios de Aceptación

- Un test envía un mensaje que supera el límite y recibe un error de protocolo;
  la memoria residente del demonio no crece de forma apreciable.
- Un test abre una conexión, no envía nada, y comprueba que una segunda
  conexión es atendida dentro del tiempo de espera configurado.
- El socket nunca es accesible a otros usuarios, ni siquiera transitoriamente,
  verificado con una `umask` permisiva en el test.
- `cargo test --workspace` en verde.
