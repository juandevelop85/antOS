# T26.3 · Controlador de Entrada Nativo: VirtIO-Input, Teclado y Ratón

> **Estado:** ✅ Completado  
> **Fase:** Fase 26 (Soberanía Bare-Metal y Desktop Nativo)  
> **Fecha:** September 2026

## Descripción
Dotar al sistema operativo de la capacidad de responder a interacciones físicas del usuario en la pantalla: pulsaciones del teclado y desplazamientos o clics del ratón. Actualmente, antOS carece de drivers de entrada en modo gráfico, impidiendo que el usuario interactúe con el entorno de escritorio visual. Este ticket implementa el controlador de entrada VirtIO-Input (y controlador PS/2 / PL050 en x86/AArch64), la cola de eventos de entrada y el renderizado del cursor del ratón sobre el Framebuffer.

## Alcance Técnico
1. **Driver VirtIO-Input (`kernel/src/drivers/virtio_input.rs`):**
   - Inicialización del dispositivo de entrada estándar VirtIO (teclado y ratón).
   - Configuración de la cola de eventos Virtqueue (`eventq` y `statusq`).
   - Atención de interrupciones de hardware generadas al presionar teclas o mover el ratón.
2. **Cola de Eventos del Kernel (`kernel/src/input/`):**
   - Definición de tipos de eventos:
     ```rust
     pub enum InputEvent {
         KeyPress(KeyCode),
         KeyRelease(KeyCode),
         MouseMove { dx: i32, dy: i32 },
         MouseAbsolute { x: u32, y: u32 },
         MouseButtonPress(MouseButton),
         MouseButtonRelease(MouseButton),
     }
     ```
   - Buffer circular con exclusión mutua para encolar eventos de entrada recibidos por interrupción.
3. **Mapeador de Teclado y Decodificador Escancode:**
   - Traductor de scancodes estándar (Set 1 / Set 2 / Linux EV_KEY) a caracteres ASCII y modificadores (Shift, Ctrl, Alt, Super).
4. **Renderizador del Cursor del Ratón en el Desktop Shell:**
   - Renderizado de mapa de bits del cursor (flecha gráfica de 12x18 píxeles con contorno).
   - Restauración del fondo previo debajo del cursor para evitar estelas o artefactos al moverse.
5. **Enrutamiento de Foco:**
   - Si el usuario hace clic en el HUD de intenciones o en la ventana de terminal, el foco de entrada se transfiere a ese componente y las teclas presionadas se escriben en su buffer de texto.

## Criterios de Aceptación
* El movimiento del ratón en UTM o QEMU desplaza fluidamente el cursor en pantalla.
* Las pulsaciones de teclas se capturan y se visualizan en la terminal gráfica interactiva.
* El soporte de teclas modificadoras (`Shift`, `Backspace`, `Enter`, `Super`) funciona correctamente.
* Pruebas unitarias de decodificación de eventos de entrada y scancodes.
