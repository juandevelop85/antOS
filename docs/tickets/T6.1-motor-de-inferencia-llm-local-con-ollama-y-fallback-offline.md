# T6.1 · Motor de Inferencia LLM Local con Ollama y Fallback Offline

> **Estado:** ✅ Completado  
> **Fase:** Fase 6  
> **Fecha:** September 2026

## Descripción
Integración de modelos locales (DeepSeek-Coder, Qwen2.5) vía Ollama y llama.cpp para operar 100% offline sin depender de APIs en la nube.

## Alcance Técnico
1. **Planificador Ollama (`OllamaPlanner`):**
   - Módulo en `system/antosd/src/planner/ollama.rs` que se comunica con el servidor local de Ollama (`/api/chat` y `/api/tags`).
   - Esquema de herramientas JSON nativo (`tools` con función `emitir_plan`).
   - Doble soporte de parsing: extracción estructurada de llamadas a herramientas (`tool_calls`) y recuperación de planes JSON embebidos en texto markdown.
2. **Jerarquía de 3 Niveles y Fallback Transparente:**
   - En `system/antosd/src/main.rs`: selección automática si no se especifica planificador:
     1. Claude Messages API (si `ANTHROPIC_API_KEY` está configurada).
     2. Ollama local (si el servidor está activo y responde).
     3. Planificador local determinista sin dependencias externas.
   - Flag explícito `--planificador ollama` o `--planificador local-llm`.
3. **Comandos de Gestión de LLMs:**
   - `antos llm status`: Diagnóstico del estado de los proveedores (Claude, Ollama y Reglas locales).
   - `antos llm list` / `models`: Lista los modelos descargados en la instancia local de Ollama.
4. **Capacidades Declarativas:**
   - `system/capabilities/llm.status.toml`
   - `system/capabilities/llm.list.toml`
5. **Pruebas y Verificación:**
   - Pruebas unitarias de parsing de respuestas con llamadas a herramientas y fallback JSON (`test_parse_ollama_tool_call_response`, `test_parse_ollama_json_fallback_response`, `test_ollama_defaults`).
