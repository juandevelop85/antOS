# T29.1 · Framework de Despacho de Comandos y Parser de Línea en el Shell Soberano

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 29 (Superficie de Comandos Soberana en el Shell Bare-Metal)
> **Fecha:** Pendiente
> **Dependencias:** T26.5 (runtime `libantos` y shell interactivo). Base del resto de Fase 29.

## Descripción

El shell soberano (`user/src/main.rs`, `antos-init`, PID 1 en EL0) resuelve
comandos con un `match` de seis brazos fijos (`help`, `info`, `ls`, `cat`,
`desktop`, `agent`). No hay tokenizador real (parte por espacios simples), ni
tabla de comandos, ni códigos de salida, ni ayuda por comando, ni forma de
añadir uno sin tocar el `match`. Es el cuello de botella para todo lo demás de
la Fase 29.

Este ticket sustituye ese `match` por un **framework de despacho**: un
tokenizador de línea con comillas y flags, un registro de comandos con
metadatos y `run()`, `help` autogenerado, códigos de salida y errores claros.
Los seis *builtins* actuales se reescriben sobre el framework sin cambiar su
comportamiento observable.

## Alcance Técnico

1. **Tokenizador de línea (`user/libantos`, módulo `shell::lexer`):**
   - Separación por espacios/tabs colapsando repetidos.
   - Comillas simples y dobles (la comilla no aparece en el token; dentro de
     dobles se permite `\"` y `\\`).
   - Comentario de línea: todo lo que sigue a un `#` no entrecomillado se
     descarta.
   - Salida: `Vec<String>` de argumentos (`argv[0]` = nombre del comando).
   - Sin pánico ante entrada malformada (comilla sin cerrar → error tipado
     `LexError`, no `unwrap`).

2. **Parser de argumentos (`shell::args`):**
   - `--flag`, `--flag=valor`, `--flag valor`, agrupación corta `-abc`, `--`
     para terminar el parseo de flags.
   - API: `Args::parse(&[String]) -> Result<Args, ArgError>` con
     `positional() -> &[String]`, `flag(name) -> bool`, `value(name) -> Option<&str>`.

3. **Registro de comandos (`shell::registry`):**
   - `trait Command { fn name(&self) -> &'static str; fn summary(&self) -> &'static str; fn usage(&self) -> &'static str; fn run(&self, ctx: &mut ShellContext, args: &[String]) -> ExitCode; }`
     (o tabla estática equivalente si el `dyn` no encaja en `no_std` sin
     `alloc` — hay `alloc`, así que `Vec<Box<dyn Command>>` es aceptable).
   - `ShellContext`: cwd, último código de salida, referencia al VFS/IPC.
   - `ExitCode(u8)` con `SUCCESS` / `FAILURE` y `From<bool>`.

4. **Bucle del shell reescrito (`user/src/main.rs`):**
   - Lee línea → *lexer* → si vacío, reimprime *prompt*; si error de *lexer*,
     imprime el mensaje y `$? = 2`.
   - Resuelve el comando en el registro; si no existe, `comando no encontrado: X`
     + (si hay uno con distancia de edición 1) `¿quisiste decir 'Y'?`, `$? = 127`.
   - Ejecuta y guarda el código de salida; `echo $?`-style expondrá el último
     código en T29.3.
   - Secuenciación con `;` entre comandos (opcional, detrás de una prueba).

5. **`help` autogenerado:**
   - `help` sin argumentos → tabla `nombre — summary` ordenada.
   - `help <comando>` → `usage` + `summary` del comando.

6. **Portado de los *builtins* existentes** (`help`, `info`, `ls`, `cat`,
   `desktop`, `agent`) al `trait Command`, con el mismo texto y comportamiento.

## Criterios de Aceptación

- El shell arranca a `antos>` y los seis comandos existentes se comportan
  exactamente igual que antes (mismo texto de `help`, `info`, `ls`, `cat`,
  `desktop`, `agent`).
- `cat "un fichero"` y `agent 'texto con espacios'` respetan las comillas
  (antes se partían por espacios).
- Un comando inexistente imprime un error claro y deja `$? = 127`; una comilla
  sin cerrar imprime un error y no cuelga ni entra en pánico.
- `help` se genera a partir del registro (añadir un comando nuevo no obliga a
  editar `help`).
- Tests unitarios del *lexer* (comillas, escapes, comentario `#`) y del parser
  de flags pasan como binario `rustc --test` independiente o `cargo test` del
  crate `user/libantos` en host.
- `cargo check --workspace`, `cargo build` del kernel para
  `x86_64-unknown-none` y `aarch64-unknown-none`, y `cargo clippy` sin
  regresión de avisos.
- `docs/manual-de-comandos.md` §E documenta el nuevo modelo de comandos del
  shell soberano.
