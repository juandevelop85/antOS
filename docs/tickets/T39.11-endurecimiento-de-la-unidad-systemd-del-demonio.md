> **Origen:** auditoría de seguridad de 2026-09-25.

## Descripción

`systemd.services.antos` en
[`system/nixos/module.nix`](../../system/nixos/module.nix) solo fija
`Type`, `User`, `ExecStart`, `Restart` y la salida al journal. No usa
ninguna de las opciones de aislamiento de systemd. El demonio es el broker
que habla con modelos remotos, aplica cambios y lanza el recinto: un fallo
en él (un parser JSON, el servidor web embebido de T16.4) tiene hoy el
alcance completo del usuario, incluidas `~/.ssh` y la sesión gráfica.

`systemd-analyze security antos.service` lo puntuaría como «UNSAFE».

## Alcance Técnico

Añadir, comprobando una a una que no rompen ninguna capacidad (Landlock,
`nix shell`, `git`, `nixos-rebuild` vía `sudo`/polkit):

- `NoNewPrivileges=yes` (compatible con Landlock, que ya lo exige).
- `ProtectSystem=strict` con `ReadWritePaths=` = `cfg.state`,
  `cfg.workspace` y `/etc/nixos` solo si `system.*` lo necesita (si no,
  delegar esas capacidades a una unidad aparte con privilegios).
- `ProtectHome=read-only` o `tmpfs` + `BindPaths=` del workspace; decidir
  qué necesita de `$HOME` (`.gitconfig`, `.ssh` solo con concesión).
- `PrivateTmp=yes`, `PrivateDevices=yes`, `ProtectKernelTunables=yes`,
  `ProtectKernelModules=yes`, `ProtectKernelLogs=yes`,
  `ProtectControlGroups=yes`, `ProtectClock=yes`, `ProtectHostname=yes`.
- `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6 AF_NETLINK`.
- `RestrictNamespaces=` permitiendo solo `user net mnt` (T39.1/T39.4).
- `LockPersonality=yes`, `RestrictRealtime=yes`, `RestrictSUIDSGID=yes`,
  `MemoryDenyWriteExecute=yes` (verificar con el intérprete WASM).
- `SystemCallFilter=@system-service` + `landlock_*`,
  `SystemCallArchitectures=native`.
- `UMask=0077` (hace innecesario el cambio temporal de umask de
  `bind_socket_with_restrictive_umask`, que además es global al proceso).
- `CapabilityBoundingSet=` vacío.

## Criterios de Aceptación

- `systemd-analyze security antos.service` ≤ 3.0 («OK» o mejor).
- El smoke de T30.4 / T36.2 pasa con la unidad endurecida: crear proyecto,
  `test.run`, `project.run`, `git.status`, actualización del sistema.
- Cada opción que no se pueda activar queda documentada en el propio
  `module.nix` con el motivo.
