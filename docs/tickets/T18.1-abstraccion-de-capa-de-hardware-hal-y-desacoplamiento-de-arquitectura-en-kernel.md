# T18.1 · Abstracción de Capa de Hardware (HAL) y Desacoplamiento de Arquitectura en Kernel

> **Estado:** ✅ Completado  
> **Fase:** Fase 18  
> **Fecha:** September 2026

## Descripción
Refactorizar el subsistema del kernel (`kernel/`) para desacoplar el código dependiente de x86_64 de los componentes agnósticos de arquitectura (gestor de memoria dinámica, tareas/cooperativo, sincronización y lógica de arranque). Crear una Capa de Abstracción de Hardware (*Hardware Abstraction Layer - HAL*) con traits e interfaces comunes de arquitectura, organizando los módulos específicos bajo `kernel/src/arch/x86_64/` y preparando la estructura para `kernel/src/arch/aarch64/` mediante compilación condicional basada en `#[cfg(target_arch = "...")]`.

## Alcance Técnico
1. **Definición de Traits HAL en `kernel/src/arch/mod.rs`:**
   - `pub trait ArchConsole`: E/S básica de depuración por puerto serie.
   - `pub trait ArchMmu`: Interfaz para inicialización y recarga de tablas de páginas (`CR3` en x86, `TTBR` en ARM).
   - `pub trait ArchInterrupts`: Control global de interrupciones (habilitar, deshabilitar, esperar interrupción, `enable_and_halt`, `are_enabled`).
   - `pub trait ArchSyscall`: Mecanismo de entrada y despacho a llamadas del sistema.
2. **Reorganización de x86_64 (`kernel/src/arch/x86_64/`):**
   - Mover `gdt.rs`, `interrupts.rs`, `port.rs`, `serial.rs` y `userspace.rs` al submódulo de arquitectura `arch::x86_64`.
   - Implementar los traits HAL para x86_64 (`X86Interrupts`, `X86Mmu`, `X86Syscall`, `SerialPort` como `ArchConsole`).
3. **Estructuración de `kernel/src/arch/aarch64/`:**
   - Crear la estructura modular para ARM64 (`mod.rs`, `pl011.rs`, `exceptions.rs`, `mmu.rs`, `syscall.rs`) e implementar los traits HAL (`ArmInterrupts`, `ArmMmu`, `ArmSyscall`, `Pl011Uart`).
4. **Verificación y Compatibilidad:**
   - Asegurar que la compilación actual para `x86_64-unknown-none` se mantiene completamente intacta y sin regresiones.
   - Eliminación de ensamblador en línea directo de módulos agnósticos (`main.rs`, `memory.rs`, `sync.rs`, `task/executor.rs`).

## Criterios de Aceptación
* El kernel compila correctamente para `x86_64-unknown-none` a través de la nueva abstracción `arch::x86_64`.
* Cero referencias directas a instrucciones o registros x86 (`inb`, `outb`, `cr3`, `rdmsr`, `wrmsr`, `sti`, `cli`, `hlt`) en `kernel/src/main.rs` o módulos genéricos.
* Estructura modular `kernel/src/arch/{x86_64, aarch64}` funcional y lista para recibir la implementación de ARM.
* Suite de pruebas del workspace y verificación del kernel 100% exitosa.

## Implementación

### Archivos Creados y Modificados
- `kernel/src/arch/traits.rs`: Creados los traits agnósticos `ArchConsole`, `ArchInterrupts`, `ArchMmu` y `ArchSyscall`.
- `kernel/src/arch/mod.rs`: Despacho condicional para `x86_64` y `aarch64` exportando `current`.
- `kernel/src/arch/x86_64/`:
  - Centralizados `gdt.rs`, `interrupts.rs`, `port.rs`, `serial.rs`, `userspace.rs` y añadido `mmu.rs` (`X86Mmu`, `CurrentMmu`).
  - Implementadas operaciones de control de CPU y breakpoint sin ensamblador en línea disperso.
- `kernel/src/arch/aarch64/`:
  - Creados módulos `pl011.rs` (driver UART MMIO para QEMU `virt`), `exceptions.rs` (`DAIF`/`wfi`), `mmu.rs` (`TTBR0`/`TLBI`), `syscall.rs` y `mod.rs` (`ArmInterrupts`, `ArmMmu`, `ArmSyscall`).
- `kernel/src/memory.rs`: Refactorizado para utilizar `CurrentMmu::read_root_table()` y `CurrentMmu::flush_tlb()`.
- `kernel/src/sync.rs`: Refactorizado para utilizar `ArchInterrupts` (`are_enabled`, `disable`, `enable`).
- `kernel/src/task/executor.rs`: Reemplazado `sti; hlt` por `ArchInterrupts::enable_and_halt()`.
- `kernel/src/main.rs`: Eliminado ensamblador directo (`int3`, `hlt`, `cli`), reemplazado por abstracciones HAL y configurado `#![cfg_attr(target_arch = "x86_64", feature(abi_x86_interrupt))]`.
- `builder/`: Verificada la creación de imágenes `antos-bios.img` a partir del kernel refactorizado.
