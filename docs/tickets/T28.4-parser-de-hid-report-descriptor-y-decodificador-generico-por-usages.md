# T28.4 · Parser de HID Report Descriptor y Decodificador Genérico Dirigido por Usages

> **Estado:** ✅ Completado
> **Fase:** Fase 28 (Periféricos Completos y Robustez de Plataforma Bare-Metal)
> **Fecha:** September 2026
> **Dependencias:** **T28.3** (enumeración xHCI fiable). Compatible con **T28.1** (misma capa `InputEvent`).

## Descripción

Los decodificadores HID actuales (`kernel/src/drivers/usb/hid/keyboard.rs`, `mouse.rs`) asumen el **layout de Boot Protocol** (8 bytes fijos). El *Report Descriptor* se descarga y se imprime en `enumerate_connected_ports` pero **no se parsea**, así que cualquier dispositivo que no hable Boot Protocol (teclados NKRO, ratones con Report IDs, mandos, digitalizadores) se decodifica mal o no se decodifica.

Este ticket implementa un **parser real de HID Report Descriptor** y un **decodificador de reportes dirigido por *usages***, de forma que el kernel entienda dispositivos arbitrarios sin código específico por modelo. El camino Boot rápido se conserva cuando `SET_PROTOCOL(Boot)` tiene éxito.

## Alcance Técnico

1. **Parser de items HID (`kernel/src/drivers/usb/hid/report.rs`, nuevo):**
   - Items cortos: prefijo `bSize`/`bType`/`bTag`.
   - **Global**: `Usage Page`, `Logical Minimum/Maximum`, `Physical Minimum/Maximum`, `Report Size`, `Report Count`, `Report ID`, `Unit`, `Unit Exponent` — con pila `Push`/`Pop`.
   - **Local**: `Usage`, `Usage Minimum/Maximum` (se limpian tras cada Main item).
   - **Main**: `Input` / `Output` / `Feature` (flags: `Constant`, `Variable`, `Relative`, `Wrap`, `Null`), `Collection` / `End Collection` (Application, Physical, Logical) con anidamiento.
   - Salida: `Vec<ReportField>` con `{ report_id, bit_offset, bit_size, report_count, usage_page, usages, logical_min, logical_max, flags }`.

2. **Modelo de dispositivo (`HidDevice` en `hid/report.rs`):**
   - Agrupar campos por `Report ID`; detectar si hay prefijo de Report ID (1 byte) o no.
   - Identificar roles por *usage*: teclas (Usage Page `0x07`), botones (`0x09`), ejes `X`/`Y`/`Wheel` (`0x01`: `0x30`/`0x31`/`0x38`), `AC Pan` (`0x0C`: `0x0238`), control de consumidor/sistema (`0x0C` / `0x01:0x80`).

3. **Decodificador genérico (`HidDevice::decode(report: &[u8]) -> Vec<InputEvent>`):**
   - Extracción de campos por `bit_offset` / `bit_size` (little-endian a nivel de bit), con signo cuando `logical_min < 0`.
   - Demux por `Report ID` (primer byte cuando aplica).
   - Teclas: diff estilo *array* (como Boot) o *bitmap* según flags → `KeyPress` / `KeyRelease`.
   - Ratón: relativo vs absoluto según flag `Relative`; los absolutos se escalan con el `logical_max` **real** del descriptor (no `0x7FFF` hardcodeado).
   - Botones por `Usage Minimum..Usage Maximum`.
   - Rueda / pan → `InputEvent::Scroll`.

4. **Integración (`kernel/src/drivers/usb/xhci/mod.rs`):**
   - Si `SET_PROTOCOL(Boot)` tuvo éxito y la subclase es Boot → seguir usando `UsbHidKeyboard` / `UsbHidMouse` (camino rápido, sin regresión de rendimiento).
   - En caso contrario → parsear el `desc_buf` ya obtenido y decodificar con `HidDevice::decode`.
   - `classify_report_descriptor` (heurística de firmas `05 01 09 06 / 05 01 09 02`) se sustituye por la clasificación del parser (usage de la colección Application de nivel superior).
   - Guardar el `HidDevice` parseado en `SlotDevice`.

5. **`GET_REPORT` / `SET_IDLE`:**
   - `GET_REPORT(Input)` por control transfer para obtener el estado inicial de dispositivos que no emiten hasta el primer cambio.

## Criterios de Aceptación

- Un ratón USB **no-boot** (Report Protocol, con Report IDs) mueve el cursor y sus botones funcionan, sin código específico del modelo.
- La tablet absoluta (VirtualBox / QEMU `usb-tablet`) escala `X`/`Y` usando su `Logical Maximum` **leído del descriptor**.
- Un teclado **no-boot** genera `KeyPress` / `KeyRelease` correctos, incluidos modificadores.
- El decodificador Boot se sigue usando cuando `SET_PROTOCOL(Boot)` funciona (verificado por traza).
- Pruebas unitarias con `cargo test --workspace`:
  - Parseo del descriptor de 8 bytes de la tablet de VirtualBox (`05 01 09 02 a1 01 …`, el del log de campo) → campos `X`/`Y` de 16 bits absolutos en offsets 32/48 bits.
  - Parseo de un descriptor de teclado Boot.
  - Extracción de campos con y sin `Report ID`, y de campos con signo.

## Estado de Verificación (September 2026)

**Implementado:**

1. **Parser de items HID** (`kernel/src/drivers/usb/hid/report.rs`, nuevo):
   - `parse_report_descriptor(&[u8]) -> Vec<ReportField>`. Items cortos
     (`bSize`/`bType`/`bTag`) y salto de items largos (`0xFE`).
   - Global: `Usage Page`, `Logical Min/Max`, `Report Size/ID/Count`, `Push`/`Pop`
     (con pila `Vec<GlobalItems>`). Physical/Unit se aceptan y descartan.
   - Local: `Usage`, `Usage Minimum/Maximum`; se limpian tras cada Main item.
   - Main: `Input`/`Output`/`Feature` con flags (`Constant`, `Variable`,
     `Relative`, `Wrap`, `NullState`); `Collection`/`End Collection` reconocidas.
   - `ReportField { report_id, kind, bit_offset, bit_size, report_count,
     usage_page, usages, usage_min, usage_max, logical_min, logical_max, flags }`.
     El `bit_offset` se acumula por `(report_id, kind)` — cada Report ID es su
     propio reporte. `usage_at(index)` resuelve página/uso efectivos (con usages
     extendidos de 32 bits).

2. **Modelo de dispositivo** (`HidDevice` en el mismo módulo):
   - `HidDevice::from_descriptor` parsea, detecta prefijo de Report ID
     (`uses_report_id`) y clasifica el rol (`HidRole::{Keyboard, Mouse, Other}`)
     por el uso de la colección Application de nivel superior, con respaldo por
     los usos que realmente portan los campos.
   - `input_len_bytes(report_id)` dimensiona el `GET_REPORT`.

3. **Decodificador genérico** (`HidDevice::decode(&mut self, &[u8]) -> Vec<InputEvent>`):
   - `extract_bits` (LE a nivel de bit) + `sign_extend` cuando `logical_min < 0`.
   - Demux por `Report ID` (primer byte cuando aplica).
   - Teclas (página `0x07`): campos *variable* (bitmap, incl. modificadores
     `0xE0..0xE7`, mapeados ahora en `hid_usage_to_key`) y *array* (estilo Boot);
     diff contra el reporte previo → `KeyPress`/`KeyRelease`.
   - Botones (página `0x09`) por `Usage Minimum..Maximum`, diff de bitmask →
     `MouseButtonPress`/`Release`.
   - Ejes página `0x01`: `X`/`Y`/`Wheel`/`Z` relativos → `MouseMove`/`Scroll`;
     absolutos → `MouseAbsolute` reescalado con `normalize_abs(raw, logical_max)`
     (identidad si `logical_max == 32767`, regla de tres en otro caso — sin
     `0x7FFF` hardcodeado). `AC Pan` (`0x0C:0x0238`) → `Scroll.delta_x`.

4. **Integración** (`kernel/src/drivers/usb/xhci/mod.rs`):
   - `SlotDevice` gana `hid: Option<HidDevice>` y `use_generic: bool`.
   - En `enumerate_device`: se lee el Report Descriptor (buffer 256 B) y se
     intenta `SET_PROTOCOL(Boot)`. `boot_ok = SET_PROTOCOL ok && subclase Boot`.
     `use_generic = !boot_ok && !hid.is_empty()`. Camino Boot → `UsbHidKeyboard`
     / `UsbHidMouse` (sin regresión de rendimiento). Camino genérico → se guarda
     el `HidDevice` y `handle_transfer_event` decodifica con él.
   - Clasificación `is_keyboard`/`is_mouse` para el volcado de `info` toma el
     `HidRole` del parser; `classify_report_descriptor` queda como respaldo para
     descriptores no parseables.
   - `GET_REPORT(Input)` (`bmRequestType 0xA1`) tras configurar el endpoint para
     cebar el estado de diff de dispositivos que sólo emiten al cambiar.
   - Volcados de `main.rs` / `usb::debug_report` muestran `[boot]` vs
     `[report descriptor]` / `boot` vs `gen` (traza del criterio 4).
