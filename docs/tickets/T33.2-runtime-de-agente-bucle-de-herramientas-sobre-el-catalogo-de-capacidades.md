> **Estado:** ✅ Completado

> **Prioridad:** 🔴 Alta
> **Fecha:** September 2026
> **Dependencias:** T33.1, T2.1/T2.2 (git y worktrees), T5.2 (bóveda),

> T31.4 (nada de `sh -c`), T31.8 (socket 0600).
> **Origen:** Hoy un modelo participa en exactamente un punto:
> `Planner::plan` convierte UNA intención en UNA lista de capacidades, de
> una sola vez y sin ver el resultado (`session::intent_session`). Construir
> software exige un bucle: leer, razonar, editar, probar, corregir.

## Descripción

antOS ya tiene lo difícil: un **catálogo de capacidades tipadas** con
efectos declarados, `tier` (`auto`/`confirm`/`grant`), reversibilidad,
radio de impacto, sandbox (Landlock/Seatbelt), snapshots, journal y
`undo`. Lo que falta es el **runtime que pone ese catálogo en manos de un
modelo como su conjunto de herramientas**, en una conversación de varios
turnos, con presupuesto y con las mismas garantías que una intención.

Diseño: un módulo `system/antosd/src/agent/` con `AgentRun` que:

1. recibe un objetivo en texto (ticket, intención larga, fallo de tests),
   un *toolset* (subconjunto del catálogo) y un presupuesto;
2. construye el prompt con contexto **selectivo** (nunca el repo entero):
   ticket parseado (`spec`), `memory.search` sobre el objetivo, `git.status`;
3. abre una conversación con el proveedor activo (`LlmConfig`): Claude por
   Messages API con `tools` (un `tool` por capacidad, esquema derivado de
   `[params]` como ya hace `planner/claude.rs::plan_tool_schema`), Ollama
   por `/api/chat` con `tools`, OpenAI-compat por `chat/completions`;
4. por cada `tool_use` que devuelve el modelo: `Catalog::validate` →
   `Blast::compute` del paso → si el `tier` lo exige, **aprobación por el
   `SessionHandler`** (la barra o el CLI, igual que hoy) → snapshot de los
   paths afectados (una vez por run, incremental) → `exec::apply` →
   `journal::append` → el resultado vuelve al modelo como `tool_result`;
5. termina cuando el modelo emite `finalizar` (herramienta terminal con
   resumen) o se agota el presupuesto (pasos, tokens, tiempo); en ambos
   casos deja `AgentReport` (pasos, herramientas, coste, snapshot id).

El modelo **nunca ejecuta texto libre**: no hay `shell.run`; lo que no
está en el catálogo no existe para él (T31.4). Un fallo de validación se
le devuelve como error de herramienta, no se corrige en silencio.

## Alcance Técnico

- **Capacidades nuevas (`system/capabilities/`):**
  - `fs.patch` — aplica un parche *search/replace* exacto (bloque
    `old`/`new`, debe casar una sola vez) sobre un fichero del workspace.
    `tier = "confirm"`, `reversible = "snapshot"`. Es la herramienta de
    edición de un agente; `fs.write` completo queda para ficheros nuevos.
  - `test.run` — ejecuta la suite del proyecto (detección: `Cargo.toml` →
    `cargo test`, `package.json` → `npm test`, `pyproject.toml` →
    `pytest`) **dentro del sandbox** con cuota, devolviendo salida acotada
    (últimas N líneas + resumen). `tier = "auto"`.
  - `fs.list` — listado acotado de un directorio (profundidad y número).
- **`system/antosd/src/agent/mod.rs`:** `AgentRun`, `AgentBudget { max_steps,
  max_tokens, max_seconds }`, `AgentReport`, `Toolset` (lista de nombres
  del catálogo; por defecto: `fs.read`, `fs.list`, `fs.patch`, `fs.write`,
  `test.run`, `git.status`, `memory.search`, `finalizar`).
- **`system/antosd/src/agent/providers.rs`:** cliente multi-turno con
  `tool_use` para Claude, Ollama y OpenAI-compat, reutilizando la
  lectura de claves de `planner/claude.rs` (`ANTHROPIC_API_KEY[_FILE]`,
  bóveda) y `LlmConfig`. Sin SDK: HTTP a mano como el planificador.
- **`system/antosd/src/agent/fake.rs`:** proveedor determinista para tests
  y CI: un guion de `tool_use` predefinido (lee → parchea → prueba →
  finaliza). Es lo que permite probar el bucle sin red ni clave.
- **Protocolo (`system/protocolo`):** `Request::AgentRun { goal, toolset,
  budget }`, `Event::AgentStep { step, tool, args_summary, outcome }`,
  `Event::AgentDone(AgentReport)`. Documentados.
- **CLI:** `antos agent do "<objetivo>" [--budget N] [--dry-run]` y
  `antos agent report <run_id>`.
- **Seguridad:** el run entero corre bajo `WORKSPACE_MUTATION_LOCK`; el
  entorno de las herramientas pasa por `sandbox::` sin secretos
  (`sin_secretos` ya existe); presupuesto por defecto conservador
  (20 pasos, 10 minutos); coste estimado en el `AgentReport`.

## Criterios de Aceptación

- Con el proveedor `fake`, `antos agent do "haz que pase el test X"` sobre
  un proyecto de ejemplo del repo de tests: lee, parchea con `fs.patch`,
  ejecuta `test.run`, finaliza; el journal tiene un registro por paso; el
  snapshot permite `antos undo` del run completo.
- Un `tool_use` con capacidad fuera del *toolset* o con parámetros
  inválidos se rechaza y el rechazo llega al modelo como resultado de la
  herramienta (test con el proveedor `fake`).
- Un paso `confirm` detiene el bucle hasta la decisión del
  `SessionHandler`; «no» aborta el run con `AgentReport` coherente.
- Presupuesto agotado → run termina limpio, con informe.
- Ninguna herramienta ejecuta un intérprete de comandos; `test.run` corre
  dentro del sandbox con cuota (test).
- Con clave real (opcional, fuera de CI): un objetivo pequeño sobre
  `system/antosd` produce un parche que compila y pasa `cargo test`.
- `cargo test --workspace` y CI en verde.

## Estado de Verificación

### 1. Los cambios

- **Capacidades nuevas:** `fs.patch` (sustitución exacta de un bloque que
  aparece una sola vez; `confirm`, `snapshot`), `fs.list` (listado acotado
  por profundidad y número, sin `.git`/`target`/`node_modules`), `test.run`
  (`cargo test --quiet` / `npm test --silent` / `pytest -q -p
  no:cacheprovider` según el proyecto; salida acotada a las últimas 120
  líneas con veredicto «TESTS EN VERDE/ROJO»). Ejecución en
  `exec/fs.rs` (`Change::Patch`, `ListDir`, `TestRun`); `Patch` reutiliza el
  interceptor VFS de `Write` (`write_guarded`); previsualización del parche
  como diff real en `preview.rs`.
- **`[effects] scratch`** (nuevo en `capability.rs`, `blast.rs`,
  `sandbox::Policy::from_blast`): artefactos de construcción que el recinto
  deja escribir pero que **no elevan el nivel ni se fotografían**.
  `test.run` declara `{path}/target/` y `{path}/Cargo.lock`. Sin esto, la
  regla «escribe ⇒ confirm» de `Blast::required_tier` (que no se toca)
  habría pedido aprobación en cada ejecución de tests. Los `scratch` con
  barra final se crean en `prepare`; Seatbelt ahora también crea los
  directorios declarados (como Landlock) — `cargo` crea `target/` con un
  temporal en la raíz + renombrado y la raíz no es escribible.
- **`system/antosd/src/agent/`:** `mod.rs` (`RunConfig`, `AgentHandler`,
  `run`: validación → blast → tier/grant → confirmación → instantánea
  incremental → ejecución → journal; presupuesto; `finalizar`; recorte de
  salidas por el centro), `tools.rs` (esquemas JSON derivados de los
  manifiestos, normalización de argumentos a cadenas), `providers.rs`
  (Claude Messages API con `tool_use`/`tool_result` y contenido del
  asistente reenviado íntegro; Ollama `/api/chat`; OpenAI-compat
  `/chat/completions`; `resolve()` reutiliza los constructores de los
  planificadores y `llm_config.json`), `fake.rs` (guion determinista,
  registra lo que «vio» el modelo).
- **`snapshot::extend`:** instantánea incremental por run.
- **Protocolo:** `agent.rs` (`AgentBudget`, `AgentStepEvent`,
  `AgentStepOutcome`, `AgentStopReason`, `AgentReport`),
  `Request::AgentRun`, `Event::AgentStep`/`AgentDone`.
- **IPC/CLI/barra:** `SocketHandler` implementa `AgentHandler` (pasos e
  informe como eventos; confirmación por la puerta `Proposal`/`Approval`);
  `remote_agent_run`; `antos agent do` (`--provider`, `--tools`,
  `--budget`, `--dry-run`, `-y`; con demonio va por IPC, sin él en proceso)
  y `antos agent report`; la barra pinta pasos e informe (la línea de
  tiempo con aprobación inline es T33.4). `cmd_agent` recibe ahora `Opts`
  (antes `-y` global no llegaba al subcomando).
- **Docs:** manual §4.2.

### Seguimiento

- **Landlock en antOS Linux:** `SYSTEM_READ_ROOTS` no incluye `/nix/store`
  ni `~/.cargo`/`~/.rustup`, así que en NixOS ningún comando del recinto
  (`test.run`, `ci.run`) puede leer su toolchain. Hay que ampliar las
  raíces de solo lectura del recinto (ticket propio).
- Tokens: Ollama y OpenAI-compat informan `total`/`eval_count`; Claude
  `input+output`. Coste en moneda: T33.5.
