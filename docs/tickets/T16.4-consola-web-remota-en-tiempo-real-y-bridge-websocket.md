# T16.4 · Consola Web Remota en Tiempo Real y Bridge WebSocket

> **Estado:** ⏳ Pendiente  
> **Fase:** Fase 16  
> **Fecha:** September 2026

## Descripción
Implementar una consola y panel web ultraligero embebido en `antosd`, permitiendo a los desarrolladores acceder, supervisar y controlar antOS de forma remota a través de cualquier navegador web (laptop secundaria, tablet o dispositivo móvil). Utiliza WebSockets para streaming bidireccional de telemetría de agentes en vivo, estado de tickets Kanban, terminal web interactiva y visor de diffs sintácticos, protegido mediante autenticación mutua por tokens criptográficos ed25519 de antMesh.

## Alcance Técnico
1. **Modelos y Protocolo IPC (`antos-protocol`):**
   - Estructuras `WebConsoleConfig`, `WebConsoleStatus`, `WebSocketMessage` y `WebAuthSession`.
   - Peticiones y eventos IPC: `StartWebConsole`, `StopWebConsole`, `GetWebConsoleStatus`, `GenerateWebToken`, `EstadoWebConsole` y `TokenWebGenerado`.
2. **Servidor HTTP/WebSocket Embebido (`system/antosd/src/web/mod.rs`):**
   - Servidor HTTP embebido en Rust sin frameworks pesados, con soporte de WebSockets para eventos de baja latencia.
   - Servido de activos estáticos autocontenidos (HTML5 semántico, CSS Vanilla moderno con tema oscuro idéntico a la barra Wayland, JavaScript puro sin dependencias NPM externas).
   - Autenticación mediante token Bearer y cabeceras criptográficas firmadas por el nodo antMesh.
   - Endpoint de streaming `/ws/events` que replica los eventos emitidos por el bus de IPC de antOS.
3. **Capacidades Declarativas:**
   - `web.start`: Inicia el servidor web en el puerto configurado (ej. `127.0.0.1:8088` o en la interfaz antMesh).
   - `web.stop`: Detiene el servidor web remoto.
   - `web.token`: Emite un token temporal de un solo uso para enlace seguro de clientes web.
4. **Comandos CLI en antOS:**
   - `antos web start [--port <puerto>] [--bind <ip>]`: Inicia la consola web remota.
   - `antos web stop`: Detiene el servidor web.
   - `antos web status`: Muestra URL de acceso, clientes conectados y estado del bridge.
   - `antos web token`: Genera enlace rápido con token de acceso seguro.
5. **Pruebas y Verificación:**
   - Pruebas unitarias de enrutamiento HTTP, negociación de handshake WebSocket, validación de autenticación por tokens y emisión de eventos mock.

## Criterios de Aceptación
* El demonio puede iniciar el servidor HTTP/WebSocket y servir la consola web autocontenida sin dependencias externas.
* Los clientes remotos autenticados reciben actualizaciones en tiempo real de tickets y actividad de agentes.
* Acceso seguro protegido con tokens criptográficos efímeros.
* 100% de compatibilidad con `cargo test --workspace`.
