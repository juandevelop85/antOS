# T38.6 · El Recinto Deja Escribir en los Sumideros de `/dev`

> **Estado:** 🔄 En Progreso
> **Fase:** Fase 38 (Gobernanza del Workspace)
> **Prioridad:** 🔴 Alta
> **Dependencias:** T33.5 (el mismo arreglo, hecho en su día **solo** para
> el recinto de macOS), [T38.5](T38.5-el-demonio-ve-las-herramientas-del-sistema.md)
> (hasta que el demonio no encontró `git`, este fallo no podía verse).
> **Origen:** uso real (2026-09-25). Con el PATH ya arreglado, crear un
> proyecto desde la barra falla así:
>
> ```
> failed midway and reverted to previous state: git init falló:
> fatal: could not open '/dev/null' for reading and writing: Permission denied
> ```

## La causa

`SYSTEM_READ_ROOTS` de [`sandbox/landlock.rs`](../../system/antosd/src/sandbox/landlock.rs)
incluye `/dev`, pero como su nombre dice, **solo para lectura**. `git`
—como casi cualquier herramienta— abre `/dev/null` para *lectura y
escritura* cuando quiere descartar salida, y el kernel se lo deniega.

Lo llamativo es que **este fallo ya se arregló una vez**: el recinto de
macOS lleva `(allow file-write* (literal "/dev/null"))` desde T33.5, con el
mismo síntoma («sin esto `git status` moría dentro del recinto»). El de
Linux se quedó sin el equivalente. O sea: arreglado en la máquina de
desarrollo, abierto en el sistema operativo que el proyecto instala.

## Alcance Técnico

- `SYSTEM_RW_DEVICES` en `landlock.rs`: `/dev/null`, `/dev/zero`,
  `/dev/full`, `/dev/random`, `/dev/urandom` y `/dev/tty`, con derechos de
  **fichero** (lectura, escritura, truncado), añadidos tras las raíces de
  solo lectura.
- Por qué no debilita el recinto: `/dev/null` descarta lo que recibe,
  `/dev/zero` y `/dev/random` solo producen, `/dev/full` siempre falla.
  Ninguno guarda estado ni saca información fuera. El resto de `/dev`
  sigue siendo de solo lectura.
- Test de regresión que fija la lista y comprueba que el derecho concedido
  incluye escritura de fichero y **no** derechos de directorio — dárselos
  haría que el kernel rechazara la regla entera con `EINVAL`, y una regla
  rechazada tumba el recinto completo.

## Criterios de Aceptación

- `git init` dentro del recinto completa en Linux.
- Crear un proyecto desde la barra pasa del `git init`.
- El resto de `/dev` sigue sin poder escribirse (el recinto no se abre más
  de lo necesario).
- Los tests del recinto pasan **en Linux**, que es donde ese módulo se
  compila.
