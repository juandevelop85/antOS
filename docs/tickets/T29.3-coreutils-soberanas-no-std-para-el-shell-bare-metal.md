# T29.3 · Coreutils Soberanas `no_std` para el Shell Bare-Metal

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 29 (Superficie de Comandos Soberana en el Shell Bare-Metal)
> **Fecha:** Pendiente
> **Dependencias:** T29.1 (framework de comandos), T29.2 (ejecución de programas externos).

## Descripción

Hoy `/bin/sh`, `/bin/parted`, `/bin/mkfs.ext4` del initramfs son ficheros de
texto de ~45 bytes (relleno de T24.2), y el shell sólo tiene `ls`/`cat` como
utilidades. Para que antOS sea usable como sistema operativo hace falta un
conjunto mínimo de coreutils **reales**, escritas en `no_std` y ejecutadas
como programas (`SYS_SPAWN`, T29.2) o resueltas como *builtins* cuando deben
mutar el estado del shell.

Este ticket entrega ese conjunto y las syscalls de escritura del VFS que
faltan (el `tarfs` está en RAM, así que la escritura es viable y se pierde al
reiniciar — aceptable).

## Alcance Técnico

1. **Syscalls de VFS de escritura (`kernel`):**
   - `SYS_FS_WRITEFILE` (crea/trunca/escribe), `SYS_FS_MKDIR`,
     `SYS_FS_UNLINK`, `SYS_FS_RENAME`. Operan sobre el `tarfs` en memoria
     (nodos dinámicos con `alloc`).
   - `SYS_PROC_LIST` (o extensión de `SYS_SYSINFO`): enumera PIDs con nombre y
     estado, para `ps`.
   - `SYS_REBOOT` con modo `reboot`/`halt`/`poweroff` (AArch64: PSCI
     `SYSTEM_RESET`/`SYSTEM_OFF`; x86_64: ACPI reset o triple *fault* de
     último recurso).
   - Todas documentadas en la tabla ABI de `docs/manual-de-comandos.md` §E,
     sin `unwrap`/`expect`.

2. **Crate `user/coreutils` (`no_std`, targets `*-unknown-none`):**
   Un binario por utilidad (o un *multicall* estilo BusyBox enlazado como
   varios nombres en `/bin`):
   - Ficheros/VFS: `echo`, `pwd`, `mkdir`, `rm`, `cp`, `mv`, `touch`, `cat`
     (reimplementado aquí para unificar con `ls`), `clear`.
   - Sistema: `env`, `uptime`, `free`, `ps`, `reboot`, `halt`, `true`, `false`.
   - Cada una: parseo de flags con `shell::args` de T29.1, mensajes de error a
     *stderr*-equivalente, código de salida coherente (`0` OK, `1` error de
     uso/E-S).

3. **Builtins del shell** (los que deben tocar el proceso del shell, no un
   hijo):
   - `cd [ruta]` (actualiza `ShellContext.cwd`; sin argumento → `/`),
     `pwd` como builtin además del binario, `exit [code]`, `echo` con
     expansión de `$?` y `$VAR` básicas.

4. **Empaquetado (`builder`):** compila `user/coreutils` para el target de la
   imagen y coloca cada nombre en `/bin` del `initrd.tar` embebido y del Live
   ramdisk. Reemplaza los *stubs* de texto actuales.

5. **`ls`/`cat` existentes** se alinean con las coreutils nuevas (mismo
   formato de salida, mismos códigos de error).

## Criterios de Aceptación

- Desde `antos>` funcionan, con comportamiento POSIX razonable:
  `echo hola mundo`, `pwd`, `cd /etc && cat os-release`, `mkdir /tmp/x`,
  `touch /tmp/x/a`, `cp /etc/os-release /tmp/x/b`, `mv /tmp/x/b /tmp/x/c`,
  `rm /tmp/x/c`, `ls /tmp/x`, `free`, `uptime`, `ps`, `clear`.
- `echo $?` refleja el código de salida del último comando (0 tras un éxito,
  ≠ 0 tras `rm /no/existe`).
- `reboot` y `halt` reinician / detienen la VM de forma limpia en QEMU
  `-M virt` (AArch64) y en x86_64.
- Las escrituras al VFS persisten durante la sesión y se pierden al reiniciar
  (documentado, es RAM).
- `/bin/echo`, `/bin/pwd`, … son ELF reales (no *stubs* de texto).
- Tests: parseo de flags de cada utilidad y lógica de rutas como pruebas
  puras; `system/run-arm.sh --test` ejecuta `echo antos-ok` y verifica el eco.
- `cargo check --workspace`, `cargo build` del kernel y de `user/coreutils`
  para ambos targets, `cargo clippy` sin regresión.
- `docs/manual-de-comandos.md` §E lista las coreutils y las nuevas syscalls.
