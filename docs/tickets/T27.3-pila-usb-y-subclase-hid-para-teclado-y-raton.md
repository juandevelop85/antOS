# T27.3 · Pila USB y Subclase HID para Teclado y Ratón en Bare-Metal

> **Estado:** ⏳ Pendiente  
> **Fase:** Fase 27 (Arranque Limine UEFI y Soporte de Plataformas Modernas)  
> **Fecha:** September 2026

## Descripción
Una vez inicializado el controlador host xHCI (Ticket T27.2), el sistema operativo requiere una pila de protocolos USB para enumerar los dispositivos conectados a los puertos del RootHub, asignarles direcciones lógicas, configurar sus tuberías de comunicación (*endpoints*) y atender la clase estándar **USB HID** (*Human Interface Device*).

Este ticket implementa el gestor de dispositivos USB y los decodificadores de reportes HID para **Teclado de Arranque (Boot Keyboard)** y **Ratón/Tablet Relativo y Absoluto**, integrándolos de forma nativa con el subsistema de eventos del kernel `GLOBAL_INPUT_QUEUE`. Esto permite que la ventana gráfica de VirtualBox capture el teclado y ratón directamente sin requerir ningún puente serie ni conexión externa.

## Alcance Técnico

1. **Gestor de Enumeración USB (`kernel/src/drivers/usb/`):**
   - Emisión del comando xHCI `Enable Slot` para obtener un identificador de slot.
   - Construcción y asignación del `Input Context` y `Device Context` (contexto de slot y contexto del Endpoint 0 de control).
   - Emisión de `Address Device` TRB.
   - Soporte de transferencias de control USB estándar sobre Endpoint 0:
     - `GET_DESCRIPTOR` (Device Descriptor, Configuration Descriptor, String Descriptors).
     - Parser de descriptores USB jerárquicos: Config -> Interface -> HID -> Endpoint.
     - `SET_CONFIGURATION` para activar la interfaz de entrada.

2. **Driver de Clase USB HID (`kernel/src/drivers/usb/hid/`):**
   - Configuración de Endpoint de Interrupción (*Interrupt IN*, típicamente Endpoint 1).
   - Asignación y enlace de un Transfer Ring dedicado para el endpoint de interrupción.
   - Activación de transferencia periódica e inicialización del Doorbell de endpoint.
   - Protocolo Boot Keyboard (Report ID 1 / Subclase 1, Protocolo 1):
     - Recepción del reporte estándar de 8 bytes:
       - Byte 0: Modificadores (Left Ctrl, Shift, Alt, GUI/Super, Right Ctrl, Shift, Alt, GUI).
       - Byte 1: Reservado (`0x00`).
       - Bytes 2..7: Hasta 6 teclas presionadas simultáneamente (*6KRO*) en códigos USB HID (Usage Page `0x07`).
   - Protocolo Boot Mouse / Tablet (Subclase 1, Protocolo 2):
     - Recepción del reporte de ratón (botones Izq/Der/Medio, desplazamientos relativos `dx, dy`).
     - Soporte para puntero absoluto USB Tablet (coordenadas $X, Y$ escaladas a la resolución de pantalla).

3. **Traducción y Encolado a `GLOBAL_INPUT_QUEUE`:**
   - Tabla de conversión de USB HID Usage IDs a `crate::input::KeyCode`:
     - Alfanuméricos (`0x04..=0x1D` -> `KeyCode::A..=KeyCode::Z`).
     - Numéricos (`0x1E..=0x27` -> `KeyCode::Key1..=KeyCode::Key0`).
     - Control y navegación (`0x28` -> `Enter`, `0x2A` -> `Backspace`, `0x2C` -> `Space`, flechas, tabulador, etc.).
   - Mapeo de clics y movimiento de ratón a `InputEvent::MouseMove` e `InputEvent::MouseButtonPress`.
   - Inyección instantánea en `crate::input::push_event(event)`.
   - Despertar de hilos bloqueados en `SYS_READ` o en el bucle del Compositor gráfico.

## Criterios de Aceptación
* El enumerador USB detecta e inicializa correctamente el teclado y ratón conectados en VirtualBox.
* Al presionar teclas en la ventana gráfica de VirtualBox, los eventos se traducen a `InputEvent::KeyPress` y son consumidos por el shell soberano (`SYS_READ`).
* Al mover el ratón o hacer clic en la ventana de VirtualBox, el cursor del Desktop Shell se desplaza y actualiza en tiempo real sobre el Framebuffer.
* Las teclas modificadoras (`Shift`, `Ctrl`, `Alt`, `Enter`, `Backspace`) funcionan correctamente en el teclado USB.
* Pruebas unitarias completas para el parser de reportes USB HID y el conversor de KeyCodes pasan con `cargo test --workspace`.
