# T35.1 · Catálogo Declarativo de Stacks y `project.scaffold` con `framework`

> **Estado:** ⏳ Pendiente
> **Fase:** Fase 35 (Proyectos por intención)
> **Prioridad:** 🔴 Alta
> **Fecha:** September 2026
> **Dependencias:** T17.3 (`project.git_init` automático), T5.3/`env.init`
> (perfil de entorno), T33.2 (toolset del agente), T34.4 (planificador y
> catálogo como datos, no código: `system/llm/models.toml`).
> **Origen:** `antos agent do "crea un proyecto en nestjs llamado antostest"`
> en la ISO en vivo (2026-09-18) no podía hacer nada: el agente no tiene
> shell por diseño y el toolset compacto ni `fs.write`. El camino que sí
> existe, `antos "crea un proyecto typescript llamado x"` →
> `project.scaffold`, tiene tres límites contrastados con el código:
> el planificador local solo distingue `typescript`/`python`/`rust`
> ([`planner/local/mod.rs:39`](../../system/antosd/src/planner/local/mod.rs)),
> las plantillas son un `match` en Rust con dos o tres ficheros por
> lenguaje y ningún framework
> ([`exec/fs.rs:339`](../../system/antosd/src/exec/fs.rs)), y añadir
> NestJS significa recompilar el demonio. «nestjs» hoy no significa nada
> para antOS.

## Descripción

Que la tecnología, el lenguaje y el framework de un proyecto nuevo sean
**datos** que antOS lee, no brazos de un `match`: un catálogo de *stacks*
en el repo, un `project.scaffold` que acepta `framework`, y un
planificador que reconoce los alias del catálogo. Este ticket deja el
andamio **sin red ni comandos**: plantillas puras y correctas
(`package.json` con las dependencias de NestJS declaradas, `tsconfig`,
`main.ts`, un test), listas para que T35.2 ejecute la instalación real.
Con solo esto, «crea un proyecto en nestjs llamado antostest» ya produce
un proyecto que un `npm install` deja funcionando.

### El catálogo

`system/stacks/<id>.toml`, uno por stack (cargado del árbol de antOS en
tiempo de ejecución con copia embebida de respaldo, como `models.toml`):

```toml
id        = "nestjs"
language  = "typescript"
framework = "nestjs"
aliases   = ["nest", "nestjs", "nest.js"]
summary   = "API HTTP con NestJS (TypeScript, Express bajo el capó)"

[toolchain]
nix      = ["nodejs_22"]          # lo que T35.2 pone en el flake/devbox
binaries = ["node", "npm"]        # lo que debe existir para test/dev

[commands]                          # SIEMPRE vectores; T35.2 los ejecuta
install = ["npm", "install"]
test    = ["npm", "test", "--silent"]
dev     = ["npm", "run", "start:dev"]
port    = 3000

[network]                           # informativo para el blast (ver T35.2)
hosts = ["registry.npmjs.org"]

[[file]]
path    = "package.json"
content = """{ "name": "{{name}}", ... "@nestjs/core": "^11" ... }"""

[[file]]
path = "src/main.ts"
from = "templates/nestjs/src/main.ts"   # o inline; `{{name}}` se sustituye
```

Stacks iniciales, con prioridad a lo que la gente pide por intención:
`typescript` (el actual, base), `nestjs`, `express`, `nextjs`, `python`
(base), `fastapi`, `rust` (bin, base), `axum`, `go`. Cada uno con **un test
que pasa** tras instalar (`npm test` / `pytest` / `cargo test` / `go test`)
— es lo que T35.3 verifica al terminar el andamio.

### La capacidad

`project.scaffold` gana `framework = { type = "slug", optional = true }` y
`package_manager = { type = "enum", of = ["npm","pnpm","yarn","uv","pip"],
optional = true }`; `language` pasa a validarse contra el catálogo (los
`language` distintos de los stacks). Sin `framework`, el stack base del
lenguaje (comportamiento actual). Efectos como hoy: `writes =
["$WORKSPACE/{name}/"]`, `tier = "confirm"`, `reversible = "snapshot"`.
El andamio escribe además `.antos/project.toml` con el `id` del stack, los
`commands` y el `port`: es lo que T35.3 y el agente leerán para no adivinar.

### El planificador

El local extrae lenguaje y framework por los `aliases` del catálogo, en
cualquier orden («un nest en typescript», «proyecto nestjs», «api con
fastapi llamada x»), y el nombre como hoy (`llamado`/`nombre`/última
palabra). Sin nombre reconocible pregunta, no inventa. Los planificadores
LLM lo reciben por el `enum`/descripción del manifiesto, que ahora lista
los frameworks del catálogo.

## Alcance Técnico

- **`system/stacks/*.toml`** + `system/stacks/templates/<id>/…` para
  ficheros largos. Entra en el `fileset` de `package.nix` (la lección de
  `models.toml`, `faa0566`).
- **`system/antosd/src/stacks.rs`** (nuevo): `Stack`, `StackCatalog::load
  (antos_root)`, `find_by_alias`, `render(name)` → ficheros; validación al
  cargar (ids únicos, alias sin colisiones, todo `commands.*` vector no
  vacío, `path` relativo sin `..`).
- **`exec/fs.rs`:** `project.scaffold` usa el catálogo; `scaffold(language,
  name)` se mantiene como alias del stack base para no romper llamadas
  existentes. Escribe `.antos/project.toml`.
- **`system/capabilities/project.scaffold.toml`:** parámetros nuevos;
  `summary` que nombra los frameworks.
- **`planner/local/mod.rs`:** reconocimiento por alias; tests con las
  frases reales de la sesión.
- **Docs:** manual §«Proyectos» (cómo pedirlo, cómo añadir un stack:
  un TOML, sin recompilar) y `docs/arquitectura.md`.

## Criterios de Aceptación

- `antos "crea un proyecto en nestjs llamado antostest"` (planificador
  local, `--dry-run`) propone `project.scaffold language=typescript
  framework=nestjs name=antostest`; también «api fastapi llamada demo» y
  «un servicio axum nombre core». Sin nombre → pregunta (test).
- Ejecutado: `workspace/antostest/` con `package.json` (dependencias de
  NestJS), `tsconfig.json`, `src/main.ts`, `src/app.module.ts`, un test,
  `.antos/project.toml` y repositorio Git inicializado (T17.3). Test que
  compara el árbol producido con la plantilla renderizada.
- Un stack nuevo añadido como TOML (test con un catálogo temporal) queda
  disponible sin recompilar; un TOML inválido (alias duplicado, comando
  vacío, `path` con `..`) se rechaza al cargar con el motivo.
- `project.scaffold` sin `framework` produce exactamente lo de hoy para
  `rust`/`typescript`/`python` (los tests existentes siguen en verde).
- En el Mac con `node`: `cd workspace/antostest && npm install && npm
  test` en verde a mano (aquí sin red por antOS; T35.2 lo automatiza).
- `cargo test --workspace`, clippy `-D warnings`, `fmt`; CI verde
  (incluido `nix build .#antosd`, por el `fileset`).

## Fuera de Alcance

- Verificación automática y agente: T35.3.
